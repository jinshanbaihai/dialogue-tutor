# DialogueTutor 1.7.0

## 目标与呈现优先级

目标是理解原理、独立应用与延迟保持，这些目标优先于操作数量、停留时长和装饰丰富度。学习界面的呈现顺序是 **交互＞可视化＞文字**：先确定学习者需要作出的判断或操作，再用图形揭示关系，最后用必要文字解释依据。完整解释持续可查，详细内容与默认展开内容分别设计。

1.6.0 的入口要求“先保留完整讲解，再穿插操作”，样章把探索放在图解之后、步进放在完整推导之后；活动因而附着在长文上。新课程从活动蓝图开始生成。旧版固定七幕、上下两半和字数下限不再决定页面结构；原题覆盖、数学条件和完整解答继续保留。

## 先选择任务范围

- 用户请求短问题或读后追问：使用下方“教学对话”，不自动制作整章课程。
- 用户请求讲解材料、题目或章节：生成可运行的单文件 HTML，使用内置组装器。模式范围读取 [modes-and-explanations.md](references/modes-and-explanations.md)。没有模式时按 `bgct` 理解。
- `bgct` 建立本次材料需要的原理并提供完整例题；`bbct` 覆盖板书及作业需要、保留板书记号和考纲边界；`olct/onct` 限于所给题目与必要前置公式。`plustts` 另交题目前行轨与答案讲解轨。
- 教材章号、考试规定和陌生术语先核对官方来源。示例：Pearson IAL S2 第六章为抽样与抽样分布，第七章才是假设检验；不同教材版次按该版目录定位。

## 生成流程

### 1. 形成目标与活动蓝图

读取 [teaching-design.md](references/teaching-design.md)、[interactive-html.md](references/interactive-html.md) 与 [visual-design.md](references/visual-design.md)。章节或讲述任务同时读取 [engagement-and-narrative.md](references/engagement-and-narrative.md)，把有后果的选择、结果呼应、挑战递进与回访入口写入蓝图。沿用已有 DeepTutor 组件时查询 [deeptutor-provenance.md](references/deeptutor-provenance.md)；使用学习效果主张时查询 [learning-evidence.md](references/learning-evidence.md)。新设计可标为 DialogueTutor 原创组合，不把所有改动归因于 DeepTutor。

蓝图每个目标填写：**实际失败实例或明确待测情形、目标能力、先备支持、学习者动作、可观察证据、可视化关系、必要解释、错误/辅助/正确后的下一步、完整解答位置、来源与适用条件**。这些字段保存为作者材料，页面只显示学习者需要的内容。

判断“交互优先”时检查学习者是否预测、分类、计算、解释或改变有意义变量；翻页、展开长文和空转按钮不算新的学习任务。没有适合的操作时，蓝图记录原因，采用解释图示或简洁文字。

### 2. 设计能够继续的任务流程

使用“可回答的挑战→操作或示例→可见结果→解释依据→独立新题”的基本流程，按先备情况调整。尚无前提的学习者可以先获得示例；已有前提的学习者可以直接挑战。整章存在新程序时至少形成一条完整例题、不同题的步骤补全、独立新题路径。

首屏呈现当前任务、必要条件与可用控件。定义长文、全部解答、历史和技术信息不占据首屏。每个任务具有明确结果和具体下一步；错误反馈指向当前误解与修复动作。学习者可以查看全解、跳过或返回。

预测型探索需要在运行或揭示结果之前提交并冻结未评分预测；使用自定义 interactive 保存阶段与历史，普通即时反馈 quiz 仅用于提交即验证的题目。参数改变后显示新的图形、数值与比较问题。操作记录只说明参与；独立题另行收集应用证据。视觉变化不能提前泄露后续同一题答案。

### 3. 制作课程并组装

新课程采用 `presentation: "studio"`；按交互参考中的真实 schema 制作 `lesson.json`，从技能目录运行：

```bash
python3 scripts/build_lesson.py --lesson lesson.json --output lesson.html
```

组装器内联课程数据、样式与脚本。`sections` 表示任务场景，`activities` 表示可操作内容，`pathways` 根据实际作答推荐具名后续活动。课程采用同一套色彩 token，图形、按钮、数学解释共用语义。

每个任务保留可查的完整解答；包含该题答案的解释入口与 `solutionId` 关联。查看全解后重试保留辅助记录。原题、提示、参考答案、自评和客观判断分别存储。不要直接修改已经生成的 HTML 来掩盖技能遗漏：先修改生成规则、课程数据或公共组件，再由组装器重新生成。

旧课程可继续使用原布局及 `--base-html`。`examples/s2-source.html` 与 `s2-interactive.json` 是 1.6.0 兼容性材料，不能作为新课程的布局范本。

### 4. 检查实际行为并评审

先核算题目、条件、图形与答案，再检查首次作答、预测冻结、提示、揭示、重试、分支、复习、刷新恢复、导出导入和窄屏布局。正文与图示的实际字号和明暗配色分别检查；数学表达使用 MathML 或已有可工作的数学排版方案。

自定义预测必须保留导入旧记录前已经发生的参考接触；结果与收束文案逐句对应实际数值、阶段和学习者事件。具体失败路径与生成配方见交互、参与与叙事参考，不能用揭示页面代替本人推理记录。

当用户要求专家评审时，执行 [expert-review.md](references/expert-review.md)：专家先审核技能，再使用技能从空白生成课程；课程被退回时，先修订技能提示词，再重新生成并复审。记录产物、版本、具体意见及裁定，不能用“专家同意”代替证据。普通短回合不启动整套评审。

最终自查：没有占位内容、没有冲突规则、范围明确、句子没有两种实质解释。检查发现的问题逐项修正。模型专家可审查设计、数学与交互；真实保持和迁移效果由实际学习记录检验。

## 教学对话

先确定当前知识点、已知前提和下一个可回答的问题。每回合只处理一个关键断点；必要时简短回顾已谈定的结论，再解释新依据，最后提出一个问题。学习者请求完整解答时直接提供完整解答。

曾经的提问跳过符号和前提，学习者连缺少什么都难以辨认。因此未知前提提供简短解释或示例，再提出建立在这些前提上的问题；可选诊断标为尝试，并允许“不熟悉，先看示例”。刚解释过的答案复述属于辅助练习。

数学解释按“这一步的用途与依据→一般关系及适用条件→题目中的代入与推算”连接，不用“显然”“易知”代替依据。原理追问先保留原题位置，解释所需原理，再回到原来的断点。需要图示或事实核查时直接使用相应工具。

语言采用并排讨论的姿态，肯定落实到具体推理或修正。关键术语首次中英并列，后续保留考试常用英文表达；常用词见 [统计术语中英对照.md](references/统计术语中英对照.md)。短回合避免无关标题、铺垫与重复总结。

## 内容与依赖

数学要求检验公式成立条件；统计分别核对抽样机制、分布、统计量与概率；经济论证连接定义、机制、图形、应用和评价。考试边界查询 [考纲与考试局.md](references/考纲与考试局.md)，按当前官方文件校准。需要比较同一对象的不同解释时，按需查询 [数学的冲突读法.md](references/数学的冲突读法.md)，不为填充固定幕次引入历史人物或争论。

本包包含运行所需脚本、样式与参考。外部板书处理、动画或写作技能仅在已提供且任务确实需要时使用；本包内规则足以生成独立 HTML。用户的新要求优先于历史布局偏好。
