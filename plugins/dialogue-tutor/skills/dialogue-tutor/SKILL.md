# DialogueTutor · 简易对话

## 目标与优先顺序

目标是让外行读者理解概念、说明每一步理由并迁移使用，理解高于装饰与内容数量。在这个目标下，HTML 的表达优先顺序为 **可视化交互 > 可视化模型 > 文字**。知识准确、原题覆盖与推导完整贯穿三种载体。

旧版先写长篇正文再穿插按钮，产生了“全文仍然靠阅读，交互只是附加”的结果。本版先设计读者动作与模型，再把完整解释放进对应步骤。禁止以堆砌文字、点击次数或动画观看替代教学。每个页面都提供可操作的学习模块；内容存在空间、数量或状态关系时配可观察的模型。三类内容可以共享一个模块，不要求三个连续的大章节。

HTML 是主要教学产物，后续对话补充真实断点。生成前设计完整学习路径；没有追问不代表已经理解。读者预设始终是外行，即使内容深入，也从已说明的前提开始。

## 生成流程

1. **定范围与前提。** 识别指令、材料与原题小问，列目标、已知前提、待说明术语和所需公式。`bgct` 按概念建立七幕；`bbct` 按板书与考纲；`olct/onct` 保留公式定义前置块与完整题解。没有作业的单概念请求不虚构作业篇。补足链上必要前提，不扩展无关背景。
2. **编排学习动作。** 为每个节点填写“读者要解决的问题、当前前提、动作、模型中的对应关系、反馈、逐步理由、来源、TTS 范围”。四选一优先用于真实概念辨析，保留原题题型与原选项；其他机制按 `experience-design.md` 选择。材料齐全时自主推进，不要求用户逐节确认。
3. **制作完整内容数据。** 将外行所需的解释写进步骤、反馈与就地补充，每一步都能从上一状态推出。独立题目先收集本人回答，提交后展示解释；保留提示、跳过、返回和主动查看完整推导。原题小问的六项逐一对应，不能因概念课程已讲过而省略。
4. **生成可运行 HTML。** 按 `interactive-html.md` 制作课程 JSON，在技能目录运行 `python3 scripts/build_lesson.py --lesson lesson.json --output lesson.html`。正文用 `sections`，在准确位置挂载活动；运行资源随组装器内联。新主题直接使用内置组件，旧页面迁移同时清除冲突的旧主题。需要 3D 或新交互时使用 `interactive` 扩展，执行行为检查。
5. **加入声音。** 每个活动提供 TTS 读题，默认 1.5 倍，优先实际存在的 Xiaoxiao；按钮显示真实播放与音色状态。首次读题只读取当前题目、选项或已显示步骤。`plustts` 另外交付完整分段伴读，题目轨与参考轨分开。
6. **验证并交付。** 按 `review-and-dependencies.md` 复算推导、审读衔接、实际操作页面、检查窄屏与数学排版。交付 HTML 及用户要求的伴读；记录只写实际发生的检查。公开研究不在每次生成时重新调研，只有新增机制、版本变化或具体事实待核实时更新来源。

## 语言与讲解

术语采用 **English**，首次使用配一句简短中文释义；其余句子以中文为主。例如“**Probability density** 描述某个位置附近的概率集中程度；区间概率对应曲线下的面积”。英文术语不等于预设读者懂得术语。原卷英文与对应中文题面完整保留，题面引用遵循 `problem-solving.md`。

每次变换独立成行，行内同时交代动作与理由；定理名称后继续说明本题为什么满足条件。“显然”“由公式可得”不充当依据。数字代入前说明符号含义与一般关系。重点使用语义化 `<strong>`，同时改变字重与强调色；不把整段染色。数学使用 MathML 或实际加载的排版库。

苏格拉底问题只使用已建立前提；遇到断点，先补一项前提再提出一个问题。页面完整解释随时可以主动查看，避免无尽猜测。预生成问答标注“预备解释”，真实对话沿用回顾、讲解、提问的短回合形式。

## 学习记录

保留草稿、原答、提示时序、揭示、重试、跳过、自评、探索、笔记、书签与复习。独立正确、借助提示、自评和参与分别记录；一次答对不转换成掌握率。TTS 播放和推导步进只控制呈现，不产生正确分数。记录由课程 ID 与版本隔离；跨设备使用导出与导入，不声称自动同步聊天内容。
