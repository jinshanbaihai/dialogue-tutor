# 专家评审与重新生成

用户要求专家把关时读取本文件。当前目标是技能持续生成有效且有吸引力的学习任务，该目标优先于仅修漂亮样例。

以往组件说明与完整正文出现不同条件，局部修补未同步生成规则。因此评审采用“技能→独立生成→实际产物→修订技能→重新生成”的循环。每次修改先对应明确失败实例，再选择禁令、生成配方、必填字段或可观察触发条件。

## 评审角色

| 评委 | 审查责任 | 实际证据 |
| --- | --- | --- |
| 教育学专家 | 目标、先备、任务顺序、渐隐、独立证据、数学解释 | 目标活动矩阵、首次作答、错误与辅助路径、全解 |
| 美术与摄影色彩专家 | 明暗、色彩关系、视觉重心、图示读性 | 真实截图、图宽与字号、语义配色及对比度 |
| 游戏策划专家 | 主动继续学习的动机、挑战、反馈、返回与收束 | 可玩路径、选择后果、修复体验、具体下一目标 |
| 叙事与艺术创作专家 | 情境需要、悬念、讲述节奏、反馈情绪 | 页面实际叙述、学习者行动和结果呼应 |

评委是模型承担的专业审查角色，不声明真实职业认证或真人审阅。游戏策划和教育学共同确认持续参与机制服务学习能力；停留时长、重复点击和奖励领取不作为教育通过依据。

## 评审顺序与交付

1. 提供技能及必要原件，让教育学与色彩评委先审查结构方案，给具体批评和实施条件。
2. 修改技能本身及真正控制生成的资源，邀请游戏策划与叙事评委；四位评委审核实际候选技能。
3. 所有评委通过技能后，将新技能、真实用户请求和必要原始材料交给独立生成者。生成者从空白工作目录生成课程数据并使用内置组装器；不要提供已做好的答案页面或要求照抄示例。
4. 专家检查真实产物，尤其由教育学与游戏策划评委实际核查正确、错误、辅助、跳过、独立题和收束路径。色彩评委读取真实截图，叙事与游戏策划评委抽查一条核心问题线的预测一致、不一致、辅助修正和跳过；保存实际输入、输出与活动 ID，并核对开场问题怎样由结果回应。
5. 退回意见先转成技能中的具体修订，再重新生成。不能只修改输出 HTML 后报告技能已经通过。修改公共组件时同步说明技能生成契约如何变化。
6. 保留每轮的技能版本、输入、可知模型标识、生成条件、产物摘要、测试结果和评审记录。只记录实际可获取的配置，不补造种子、温度或真实学习成绩。

课程存在预测探索与动态收束时，实际检查增加以下已暴露风险；固定输入与输出写进记录：

- 只揭示结果、没有模拟或作答便进入结尾，检查是否虚构学习者计算、归组或掌握。
- 先导出未看参考的记录，再打开全解并导入旧记录，提交新预测；检查运行时、组件和显示的辅助口径，并检查打开全解后立即提交的时序。
- 直接观察后以同条件开始新一轮，再判断须标明已见该结果；导入旧记录和刷新不擦除已发生的相关接触，改变条件不误标无关参考。
- 改变参数使比较量相等，核对图、数值和叙述；首轮与重新开始都检查。
- 先查看全解再直接观察，及揭示前后，检查“首次”“差异”“尚待揭示”等词是否符合实际阶段。
- 图形说明所称的填色、轮廓与形状必须对应真实 SVG；视觉审核仍使用渲染后的截图。

每份评审先列产物优点，再列 `Critical`、`Important`、`Minor`；意见包含具体位置、观察到的现象、影响及复查方法。主作者逐条复述并核对依据，采纳后说明改动；驳回时说明当前任务中不成立的原因。复审仅针对此前 Critical/Important 与对应改动，新增缺陷另行说明来源。

通过需要无未解决 Critical/Important；Minor 逐条修正或记录裁定。专家通过只覆盖已经检查的技能与产物版本。流程进行到可交付状态；遇到外部访问或工具条件中断时保存具体剩余项目，不制造通过结论。
