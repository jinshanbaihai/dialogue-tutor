# 交互教学、模型与视觉设计

目标是外行能够解释与迁移，理解高于装饰；在此目标下优先交互，再用模型，最后使用必要文字。下面的配方针对已出现的失败：旧样章以全文阅读为中心，交互集中在正文之后；推导说明容易变成长段；旧纸张色与干眼偏好被扩展成整站审美。

## 学习单元的形状

每个单元围绕一个需要回答的问题，先说明读者已有的前提，再安排 **预测或尝试 → 操作或观察 → 就地反馈 → 行行理由 → 新情境检验**。这是可调整的教学过程，不强制每句话都配一道题。没有足够前提时先用一个具体示例或模型建立直觉，再提出问题。

桌面空间允许时，将交互任务与模型并列，当前推导紧邻模型；窄屏按任务、模型、当前步骤的顺序排列。首个教学屏幕出现可操作任务或带观察问题的模型，避免长篇前言。后续单元保持就地反馈，避免把练习聚集在章末。导航、笔记与复习收进次级区域，不占据主要教学位置。

七幕与六项题解仍完整可达，但不要求七段或六段默认展开的长文。条件、符号含义、当前步骤理由保持可见；历史、替代解释、额外举例按需展开。读者可以返回前步，主动查看完整推导，或者跳过问题继续学习。折叠不能隐藏解题需要的初始条件。

## 选择交互机制

四选一是新写概念辨析的首选：一个明确问题、四个合理候选、唯一正确选项；每个干扰项对应具体误解，提交后反馈解释所选项的推理断点。只有二元判断时保留二选一，禁止为了凑数制造无意义答案。原题选项与题型原样保留。

| 目标 | 交互与反馈 | 当前实现 |
| --- | --- | --- |
| 辨别两个相似概念、预测变化 | 四选一；提交后说明选项为什么成立或不成立，再给迁移题 | `quiz/choice` |
| 回忆术语、条件与反例 | 概念卡先回忆后翻面；背面含简短定义、例子与边界，自评与客观作答分开 | `flashcards` |
| 理解参数怎样影响结果 | 先预测方向，再拖动 slider 或 movable point；同步图形、数字与表达式，要求找到目标或反例 | `explore` 或 `interactive` |
| 理解步骤顺序或定位错误 | 排列推导、选择第一处错误、选择下一步依据；反馈指出具体前提 | 选择题用 `quiz/choice`，排序界面用 `interactive` |
| 理解条件与结论的依赖 | 切换条件、比较正例与反例；显示改变的条件怎样影响结论 | `interactive` |
| 验证计算与推理 | 数值核对明确容差；开放解释保存原答，对照完整解法自评 | `quiz/numeric` 或 `quiz/open` |
| 应用到新的场景 | 情境分支、角色任务、反事实选择；反馈针对本次决策依据 | 预生成分支用 `interactive`，明确标注范围 |

自定义组件负责呈现与探索，`dt:exploration` 不记录正确分数；需要独立正确性证据时配标准 quiz。分支不会冒充实时 AI。初次选择机制读取 `interaction-research.md`，来源允许 DeepTutor、Brilliant、Desmos、Duolingo 等官方已核实机制；组合与扩展明确标作本项目设计。

吸引注意力来自可检验的悬念、操纵后的反馈与适当挑战。禁止用倒计时、无关弹跳、连续庆祝或强制作答维持注意力。点击“下一步”只是阅读动作，需要选择依据、找反例或新题才能检查理解。

## 行行推导的内容配方

一串等号挤在同一行会藏掉变换。每个变换单独显示，当前步骤填写四个内容槽位：

| 槽位 | 面向外行的写法 |
| --- | --- |
| 前一步 | 明确指出继承的量、条件或已建立结论；当前页保持上一状态可查 |
| 本次动作 | 显示这次只改变了什么，等号、代入、展开、边界处理分别说明 |
| 为什么允许 | 写出具体规则，解释本题怎样满足条件；第一次遇到的新规则就地补足含义 |
| 得到什么 | 当前表达式与一句结论，说明这个结果怎样为下一步提供依据 |

四个槽位可以合成两句自然解释，不强制重复四个标签。默认只显示当前步骤与简短依据；“为什么”展开基础解释，历史步骤可回看，完整推导可一键展开。完整推导仍逐行排版，不能切回多等号长段。

例如解 `2x + 3 = 11`：先说明等式两边表示相同数量；下一步分别减去 3，理由是两边拿走相同数量后仍相等，得到 `2x = 8`；再把两边各分成两等份，理由是两边同除以非零的 2，得到 `x = 4`。更深的内容沿用同一结构，不能用“线性”“归一化”等尚未解释的术语跳过理由。

模型和公式用同一颜色表示同一对象，当前改变部分只局部强调。换元说明新旧变量关系与边界，约分前说明除数非零，不等式说明方向变化，多解说明取舍，单位与范围逐步保留。不能从答案反推并跳过真实计算。

## 二维、三维与 Manim

用户提到的名称是 **Manim**。3Blue1Brown 的原始项目与 Manim Community 是不同实现，调用时选择实际环境版本，不混用 API。借鉴的重点是对象身份连续、颜色对应、几何直觉与公式变换的同步。

| 概念关系 | 载体选择 | 实際验收 |
| --- | --- | --- |
| 平面数量、函数、面积、集合 | 内联 SVG/Canvas 的二维模型 | 改变参数时图形、标签与数值由同一状态计算；轴、单位、范围明确 |
| 深度、空间旋转、截面、三维向量 | 可旋转或切片的三维模型 | 可控制视角、还原视角、显示轴和截面；同一数值关系经计算核对 |
| 必须连续观察的预先编排过程 | Manim 动画加播放、暂停、进度控制及对应解释 | 实际渲染成功；暂停时能辨认对象与步骤，媒体随交付附上 |
| 离散代数变换 | 推导步进并联动图形 | 每一步都有理由，前进、回退、重置与完整查看有效 |

二维足以解释时采用二维；三维只在深度本身帮助理解时采用。视频播放不能代替参数实验。二维图形、SVG 或 CSS 卡片翻转不标称三维数学模型。Manim 环境缺席时实现可操作的 HTML 模型并说明载体，不把分镜当成已渲染动画。

## Apple / Emil 视觉配方

旧版以偏黄纸张底、棕色强调与大面积暗卡模拟“护眼”，产生用户指出的审美失败。新页面以中性空间、清晰层级和克制反馈形成质感，干眼偏好通过可调字号、TTS、减少动效与主题选择体现，不预设某种配色有医疗效果。

| 角色 | 浅色起点 | 深色起点 |
| --- | --- | --- |
| 页面背景 | `#F5F5F7` | `#151619` |
| 内容表面 | `#FFFFFF` | `#202226` |
| 主要文字 | `#1D1D1F` | `#F5F5F7` |
| 次要文字 | `#62646B` | `#B5B7BE` |
| 交互与重点 | `#005FCC` | `#8CBFFF` |
| 正向反馈 | `#16715C` | `#78D7B5` |
| 修正反馈 | `#A33742` | `#FFACB4` |

这些是本项目设计 token，不宣称是 Apple 官方规范。图形可增补少量语义颜色，标签、线型与文字同时传意。强调色和背景一起检查可读性。正文 `<strong>` 同时使用字重与强调色，每个解释单元强调一至两个关键关系，避免整段高亮、荧光与大面积渐变。

采用 `-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif` 字体栈。正文约 17–18px、行高约 1.7、阅读宽度约 66–72ch；模型可使用更宽空间。标题通过字号、字重和留白分层；中文正文不使用负字距。模块圆角约 16–20px，按钮约 10–12px，细边线与浅阴影，避免层层套卡。玻璃效果只用于必要的浮动导航，正文与公式保持实底。

按压即时反馈，离散界面过渡约 150–250ms，使用 `cubic-bezier(0.23, 1, 0.32, 1)`；拖动时模型跟随输入，不插入延迟或禁止输入。界面动效与教学过程分开：模型变量变化按真实关系绘制，不能为了只动 transform 而冻结图形。频繁键盘动作直接更新；hover 效果只在精细指针可悬停设备启用。`prefers-reduced-motion` 使用静态切换或轻淡入，保留教学状态。控件触控区域约 44px，具名、键盘可操作，焦点清晰。

实施时读取可用的 `emil-design-eng`、`apple-design`；新增动效再读 `animate`。公开包内置以上配方，私有依赖缺席不阻止生成，也不复制私有 skill 全文进入公开仓库。

## TTS 与文字的边界

每个交互活动都有读题入口，默认 1.5 倍；播放、暂停、继续、停止、调速均显示状态。优先 `getVoices()` 实际返回的 Xiaoxiao，等待 `voiceschanged` 更新；未提供晓晓时显示实际中文音色名称，未提供语音时保留题面并显示当前状态。不能仅把默认系统语音重命名为晓晓。

读题只取题干、选项与当前可见内容，不读取整个 DOM；隐藏答案、卡片背面与后续推导不能提前进入读题。换活动或步骤后停止旧朗读，避免声音和页面错位。题干有复杂公式时在纯文本 prompt 中写出可朗读含义；步骤中使用 MathML 时，为 math 元素填写完整中文 aria-label（例如二分之一），runtime 将其作为该公式口播。术语仍保留英文，不能把分子分母直接连读。

页面读题是所有 HTML 的基础能力。`plustts` 是额外的完整讲师伴读，两者不可互相替代。真正指定晓晓的跨设备音频可通过已配置的 Azure Speech 在生成端预合成，使用 `zh-CN-XiaoxiaoNeural`；合成加速与播放加速只采用一处，避免 1.5 × 1.5。没有合成服务时提供实际系统音色与明确状态，不声称已生成晓晓音频。
