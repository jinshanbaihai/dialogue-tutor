# 数学学习界面的色彩与视觉组织

## 目标与观察依据

当前目标是让学习者先辨认操作、数学关系和反馈，这个目标优先于装饰。1.6.0 的原讲义、组装器与运行组件分别定义暖纸、褐色和鼠尾草绿；暗色图示保留黑色标注，实算对比仅 1.208:1。嵌套双图把 15px 标注缩成约 10.74px。新版本采用共享语义色与宽幅任务舞台。

视觉方向来自色彩专家的构图判断：深墨蓝提供结构，冷白承载推理，铜橙标明可行动的位置。明度先组织前后层次，色相再表达功能。这个方向是本项目的审美选择，不署名为任何真实艺术家认可。

同一量在控件、公式、标注和图形中保持相同语义。正确与错误同时提供文字和符号信息；面积填充采用透明色时另配轮廓、纹理或清晰标名。不能只凭红绿或低对比透明区域传达答案。

## 页面构成配方

首屏直接呈现当前任务。短标题、任务导航、必要场景与一项主要活动组成页面；收藏、笔记、复制上下文和技术来源进入“学习工具”。完整讲解通过具名入口展开，避免三层卡片继续压缩图形。

文字内容宽度约 700–760px；互动舞台可以扩到约 1040–1120px。这些是可调工程起点。单幅图的实际宽度不足 380px 时，双图转为上下排列。正文至少 16px，持续使用的标签和图示标注至少 14px；检查 SVG 经 viewBox 缩放后的实际字号。窄屏图示可以采用自适应 viewBox、减少刻度或另设纵向布局，不能靠整体缩小隐藏信息。

建立清晰的主次动作：当前提交、预测或实验按钮使用主动作色；导航与辅助动作降低视觉权重。标题采用简洁有力的层级，正文使用易读系统字体；数字、概率和统计量提供足够留白。动画只解释状态变化，提供 `prefers-reduced-motion` 支持。

## 具体验证

实际渲染后分别检查首屏、图形、正确反馈、错误反馈、提示、选中状态、键盘焦点、展开全解和窄屏。透明填充先与真实背景合成，再测量最终对比。核查正文对比至少 4.5:1，必要控件边界与图形至少 3:1；主题切换后重新核查。装饰分界线可低于控件边界标准，不能用装饰分界线替代输入边界。上述读性判据参照 [W3C 对比说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 与 [非文字对比说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

专家审核使用真实截图与计算结果。只审查色值表不足以通过实际页面；字号、图宽、焦点与被遮挡内容需要检查渲染后的状态。
