页面每个活动的 TTS 读题是基础功能；本文件仅规定 `plustts` 额外交付的完整伴读。

详细规则保留原有章节编号；编号与现行文件的对应见 [技能入口](../SKILL.md)。内容覆盖按本文件执行，页面编排按 [交互教学设计](experience-design.md) 执行。完整讲解通过按需展开、逐步推导与就地反馈提供，文字数量不作为完整性指标。

### 六、plustts：另交一份伴读讲解稿 ★ 2026-08-29 定的场景，2026-08-30 讲师化返工

`plustts` 跟在三个指令后面（`bgct plustts`、`bbct plustts`、`olct plustts`）。
HTML 照原指令做完做好，之后**另交一份讲解稿**，他用 TTS 收听。

**这一版换了场景。** 2026-08-20 那版把讲稿定成逐字朗读，2026-08-27 那版换成
先听后读的先修课。这一版把讲稿摆回 HTML 旁边：**HTML 是底稿，我是站在它前面讲课的那个人，
他一边听一边看着屏幕。**

场景用他的话记在这里：**把所生成的 HTML 当作底稿，在此基础上当一个讲师，
讲解稿是对整个 HTML 的完整讲解，完全跟着读者阅读 HTML 的顺序。
目标受众需要完整理解整个 HTML 的内容，可是有干眼症，所以他要用听觉辅助；
听的途中他是看着屏幕的，听到的详细程度绝对不能低于屏幕的详细程度，
甚至应该具备引导视觉的功能。**

阅读负担通过分段、TTS、字号与主题设置调整；当前默认配色遵循 experience-design.md 的中性主题，不沿用旧版冷底暖字或全深色要求。

听完的效果拿一句话来量：

> **他从头到尾把这份 HTML 听完了，屏幕上每一处都被指到过、被讲到过；
> 中间眼睛累了闭上几分钟，睁开的时候一句话就接回原位。**

#### 定位：讲师，不是读 PPT 的学生 ★ 这一句管着本节其余全部

他 2026-08-30 用一句话把这一节的病根说穿了：
**你现在的做法是分不清讲师和读 PPT 的学生之间的区别，你扮演的是前者。**

两者面对同一份材料，嘴里出来的东西完全不同：

| | 读 PPT 的学生 | 讲师 |
|---|---|---|
| 眼睛在哪 | 盯着屏幕，照着念 | 心里装着这门学科，屏幕只是提词 |
| 嘴里说什么 | 屏幕上写了什么 | 这件事情本身是怎么回事 |
| 遇到一张表 | 报行号、报栏名、逐格复述 | 讲这张表在回答什么问题，然后一步一步走它的逻辑 |
| 遇到中英双栏 | 「左边中文，右边英文」，两边都念 | 用中文把题目讲清楚，考卷上的词保持英文 |
| 听众带走什么 | 知道那一页长什么样 | 知道这个数学为什么成立 |

**拿不准某一句该不该写，就问它一句：这句话是讲师会说的，还是照着屏幕念的人才会说的。**
本节后面「带路与报版面的分界」「讲题，不是读题」两小节，是这一句在具体地方的落法。

三样载体也容易混，一并分开：

| 载体 | 它的做法 | 这一版取哪一样 |
|---|---|---|
| 朗读稿 | 把 HTML 上的字念一遍 | 不取。念稿把讲解降级成了字幕 |
| 先修讲稿（2026-08-27 那版） | 通读之前先听一遍机制与比喻，几乎不碰计算 | 退成退路，他说「先听后读」「预习版」的时候用 |
| **伴读讲解稿（这一版）** | HTML 当底稿，讲师在它旁边把每一块讲透，眼睛跟着声音走 | 取这一样 |

底稿的意思是：**页面上写着的每一样都要讲到，并且讲得比它多。**
老师手上那份讲义写着「第 3 行：k 与 s 无关，定积分对常数因子是线性的」，
他站在讲台上说出来的是一整段：为什么 k 提得出来、提出来之后式子长什么样、
哪一类同学会在这里把 k 一起积掉。纸上那一行是底稿，嘴里这一段才是讲课。

#### 三条地板：顺序、详细度、覆盖

**一、顺序地板：完全跟着读者的阅读顺序。**
讲稿的段落顺序等于 HTML 从上到下的块顺序，一块不换位、一块不合并、一块不跳过。
按章重排、把同类的表凑到一处讲、把下半八道题合成一节，这几样都会让他的眼睛跟丢。
他滚到哪里，声音就在哪里。

**互动页面按可见阶段对应讲稿。** 旧做法在问题之后留空白便接着念答案，普通 TTS
不会把空白识别成“等待提交”，答案会在学习者作答之前出现。因此，课程的 `tts.segments`
把讲解、活动提示、反馈分开，分别使用 `narration`、`activity`、`feedback`。
首次作答轨保留讲解和活动提示，到题目处明确提醒暂停；答案、解法与翻卡背面进入独立的参考答案轨，
学习者作答或主动揭示后再播放对应部分。纯文本没有自动暂停或页面同步能力，讲稿不声称具备这两项。
两个轨道合起来覆盖完整 HTML，详细度要求照旧；字段和文件名见 `interactive-html.md`。

**二、详细度地板：耳朵听到的不低于眼睛看到的。**
屏幕上任何一个读得到的元素，讲稿里都有对应的话，**覆盖每项学科信息，不用同义反复增加长度**：

- 推导表每一行：等号念出来，右列那句「凭什么」跟着念，并且展开成完整的一句话。
  念法照下面「带路与报版面的分界」：讲这一步在做什么，别报它是第几行。
- 静态定义卡每一行：一问一答都念到，最后那条结论行念完停一拍。
  提取练习的翻卡另按活动正面与反馈背面分轨，首次作答轨不念尚未揭示的背面。
- 表格每一行：按逻辑顺序讲清变量与关系，用内容名称定位，不报行列坐标。
- 题干随身块：整块念一遍，他手边不必回滚。
- 例题卡与题干块：把题目**讲出来**，情境、给定的量、单位、取值范围、问什么、分值一样不少，
  可是用讲的，不用读的（本节「讲题，不是读题」）。英文原题那一栏不整段念。
- 折叠块（小测答案）：首次作答轨讲题目与暂停提示；参考答案轨完整讲解答案。
  主动揭示与独立作答分开记录，空白段落不当作答案的揭示开关。
- 得分位置、失分点、附录、末尾的说明：一样都别落下。
- 图与 SVG：说清楚它在哪里、什么形状、坐标轴是什么、哪一块被涂了颜色、它回答哪个问题。

反过来覆盖每项学科信息，不用同义反复增加长度：讲稿里可以有 HTML 上没有的话，衔接、带路、把「凭什么」说得更细，这些都算。
**收窄不算。** 把六行推导念成「这里积分一下得到 0.19」，就把详细度压到屏幕之下了。

题面那几块把这条地板顶到作业原文那一档：随机、每一组抽完放回、恰好、至少、只用，
这类限定词在中文讲述里一个不落。英文原题照旧不整段念（§1.95）。

**三、覆盖地板：一块也别漏。** 跟 §1.9「一个也别漏」是同一条纪律。
下半几十个小问就是几十段，从第一题第一个小问按编号点到最后一个，缺一段补一段。

#### 引导视觉：声音替眼睛带路

这是这一版新长出来的那件工作。他看着屏幕，可是眼睛不能久盯，
所以每一块开口的第一句先把眼睛放到位，让他一眼落定，用不着满屏去扫。

带路的三样素材，页面自己就有：

1. **颜色。** 使用实际页面的语义色，说明当前被强调的对象；不要沿用旧版黄橙标题、白字深卡的固定词典。
2. **形状与位置。** 描述当前可见模型、曲线或活动，避免要求读者寻找已经滚出视野的对象。
3. **内容名称。** 优先引用当前标题或变量名，再讲它回答的问题。

一句定位话例如：“现在进入 Perimeter 模型，蓝色线段标出了长方形的完整边界；我们计算沿边界走一圈的长度。”配色描述与实际页面对应，颜色之外同时给出对象名称。

三条讲究：

- **先带路，再讲内容。** 顺序反过来，他要一边听一边找，两件事都做不好。
- **落到看得见的特征上。** 「上表」「前面那张图」「左边这一项」在他的屏幕上失效，
  跨屏指代那条禁令在耳朵上更严：他的眼睛正在别处。
- **翻页的地方说一声。** 「这一块到这里为止，接下来滚过一整块蓝色的题面，
  停在那个写着 CHECK 的框上。」

#### 闭眼段：给眼睛安排的休息

干眼症的常规建议是每盯二十分钟屏幕，抬眼看二十英尺外二十秒。
这条 20-20-20 是 Jeffrey Anshel 大约 1991 年提出来的，美国验光协会与美国眼科学会都在用；
提出者本人说过它当初是一句好记的口头建议，支持它的实验证据并不厚实，这一点照实写在这里。
讲稿把这件事排进去：

- 每一大块收尾的地方，凡是接下来那一段用不着看屏幕的（回顾、来历、边界、结论），
  开口先说一句「这一段你可以把眼睛闭上，屏幕上暂时没有新东西」。
- 那一段讲完，再说一句「睁开，你现在应该看着⋯⋯」，把他放回准确的位置。
- 一份讲稿里这样的段落排到每十五到二十分钟一处，位置挑在自然的段落边界上。

闭眼段的内容照旧算数，详细度地板在这里同样成立；变的只是这一段不点屏幕上的东西。

#### 一段示范：同一处推导，三种腔调

底稿（HTML 上那张推导表的第 2 行与第 3 行）：

| 行 | 内容 | 这一行凭什么 |
|---|---|---|
| 2 | k ∫₂¹⁰ (s−2)(10−s) ds = 1 | k 与 s 无关，定积分对常数因子是线性的 |
| 3 | (s−2)(10−s) = −s² + 12s − 20 | 多项式乘法；展开之后才好逐项积分 |

念稿腔（别这样写）。把字念一遍，依据当标签贴上去，没有讲：

> 第二行，k 乘以积分从 2 到 10，括号 s 减 2 括号 10 减 s，ds，等于 1，
> 依据是 k 与 s 无关，定积分对常数因子是线性的。

报版面腔（更别这样写）。依据展开了，可是每一句都在讲这张表长什么样：

> 第 2 行。内容：k 提到积分号外面。凭什么：屏幕右边那一列写着，
> k 与 s 无关，定积分对常数因子是线性的。往下一行，第 3 行。内容：把括号乘开。
> 凭什么：多项式乘法。

伴读腔（要这样写）。同样的依据，用讲课的话说出来：

> 这一步把 k 从积分号里面提到了外面。凭什么提得出来？
> k 是一个常数，它跟积分变量 s 没有关系；
> 而定积分对常数因子是线性的，常数乘进去再积，等于积完再乘。
> 提出来之后，剩下要积的只有 s 那一坨，式子干净了。
> 这里最容易出的岔子，是把 k 也当成 s 的一部分一起积掉，那样会多出一个 k 的一次方。
>
> 接着把括号乘开。s 乘 10 得到 10s，s 乘负 s 得到负 s 平方，
> 负 2 乘 10 得到负 20，负 2 乘负 s 得到正 2s。
> 合并同类项，10s 加 2s 是 12s，所以整个式子是负 s 平方，加 12s，减 20。
> 为什么要先乘开，因为逐项积分要求每一项是 s 的幂；
> 乘积那个形式，没有现成的积分法则接得住。

三段的依据是同一条，长度也差不多。分别在于：伴读腔从头到尾说的是数学，
另外两种花了不少字在说这张表自己。

#### 带路与报版面的分界 ★ 2026-08-30 补，来自第一份实物的返工

按这一版跑出来的第一份实物（S2 CH6）他判为不合格，原话记在这里：
**为什么要写上一行、下一行这种频繁出现，人类要学的是数学或者统计学这种学科知识本身，
不需要重复上一行下一行，因为这个人类学的是学科本身，不是排版或者平面设计。**

病根是把带路话铺到了每一行上。那一份里「第 N 行」出现了 396 次，
「凭什么：」286 次，整个下半的骨架都是在报表格坐标。

**带路是每一块开口一次的事**，把眼睛放到位就收手。进了一块之后再报行号、报栏名，
那就从讲学科滑到了讲版面。听的人要的是统计，不是这张表长什么样。

| 在讲版面（别这样） | 在讲学科（要这样） |
|---|---|
| 「第 2 行。内容：k 提到积分号外面。凭什么：k 与 s 无关。」 | 「先把 k 提到积分号外面。凭什么提得出来，因为 k 是常数，跟积分变量 s 没有关系，而定积分对常数因子是线性的。」 |
| 「表头橙字，三个列名是：行、内容、这一行凭什么」 | 直接开讲第一步。这张表长什么样，块开头那句带路话已经交代过了 |
| 「凭什么那一栏写着……」「右边那一列给了半句话」 | 把那半句依据当成自己的话讲出来，不提它印在哪一栏 |
| 每一步都报一句「加粗的结论」 | 走到那一步自然地说「这就是答案」。配色留给块开头那一次带路 |
| 「第 1 行……第 2 行……第 3 行……」 | 用数学自己的连接词往下走：「先」「凭什么能这样」「接着」「代进去」「最后」 |

**块之内保留的锚点只有两种**：走到关键处的一次提示（「这一步是全题最容易错的地方」
「最后一步了」），以及那一步在屏幕上有特殊标记时的一次点名（「这一步屏幕上已经强调，
它就是答案」）。行号本身不出声，它对理解数学没有贡献；顺着往下走，眼睛自己跟得上。

**详细度地板一点没松。** 每个等号照旧念出来，每条依据照旧展开成完整的一句话，
少掉的只是「第几行」「哪一栏」这几个字。判法一句话：
**把讲稿里所有的行号与栏名删干净，读起来仍旧是一段完整的数学讲解，那就对了。**

#### 讲题，不是读题 ★ 2026-08-30 同日补

同一次返工他还点了两处，跟行号是同一个病：

**一、卡片的左右两栏不报。** 他的原话：**你不要反复给我讲左边中文题面，右边英文题面，
这是浪费我的时间，我学的是具体的知识。** 例题卡在屏幕上分左右两栏，那是版面。
讲的时候直接进题目，用不着交代它排成几栏、哪一栏装什么。

**二、英文原题那一栏不整段念。** 他的原话：**这个讲解的核心语言是中文，非术语不用英文。**
右栏的英文是左栏的同一件事换一种语言，念它带不来任何新的学科信息。
核心考试词照旧保持英文（population、statistic、critical region、binomial、H nought
这些考卷上原样出现的词），句子本身用中文。命令动词是个例外，
它决定怎么答，所以照旧点名：Show that、Write down、Suggest、Identify、
State、Comment、Find the critical region。

**三、题面要讲，不要读。** 他的原话：**你需要讲题，不是读题。**
照读是把题面一字一句搬进耳朵；讲题是把这道题在问什么说清楚。信息一样不少，
形状不同：

| 读题（别这样） | 讲题（要这样） |
|---|---|
| 「左栏中文题面：一个袋子里有 50 个 counters，每个上面写着数字 4、7 或 10，三者数量比依次为 2 比 3 比 5，比例加粗……右栏英文原题：A bag contains 50 counters, each with one of the numbers 4, 7 or 10……」 | 「这道题给你一个袋子，里面 50 个筹码，写着 4、7、10 三种数字，个数按 2 比 3 比 5 分。从里面**随机**摸 2 个，两个数字记作 D₁ 与 D₂，**随机变量** M 是这两个数的 mean。第一问要你证明 M 等于 4 的概率是二百四十五分之九，1 分。」 |
| 「a，证明……b，求……c，计算……」逐条照抄 | 一次只交代当前这一小问要什么，做完再进下一问 |
| 把「加粗」「紫字」「共 10 分 · 三小问」也念出来 | 分值照旧要说，因为它昭示方法；字体与配色留给块开头那一次带路 |

**地板管的是学科信息，不是屏幕上的字符。** 一份英文原题、一次左右分栏、一个行号，
删掉之后他对统计的理解不少一分，那就删。一个等号、一条依据、一处失分点，
删掉之后他就少知道一件事，那就留。这一条是三条地板的解释规则，遇到拿不准的元素时按它裁。

#### 为什么这样讲，依据与本课程选择分开

| 依据 | 出处 | 落成讲稿的哪个动作 |
|---|---|---|
| 语音与文字组合的效果受条件影响 | Adesope & Nesbit 2012，DOI 10.1037/a0026147；57 项独立研究，多数在高等教育情境。总体上 spoken-written 优于 spoken-only，与 written-only 无总体差异；先备知识、节奏与图像会调节效果 | 讲稿与当前内容对应。完整而细致的伴读是本人的使用偏好；该元分析不规定逐字重复或字符比例 |
| 复杂长段仍可能产生瞬时信息负担 | Wong、Leahy、Marcus 与 Sweller 2012，DOI 10.1016/j.learninstruc.2012.05.004；比较不同长度的动画、语音与文字材料 | 持续显示公式、允许回查与学习者控制步进；屏幕上有文字不等于负担已经消除 |
| 信号提示的采用 | 多媒体学习中的 signaling 思路；本页具体设计依据见 `learning-evidence.md` | 块开头用一句提示定位当前内容，块内继续讲学科；该设计效果由具体页面检查 |
| 分段与学习者控制 | Rey et al. 2019，DOI 10.1007/s10648-018-9456-4；56 项 investigations、88 个比较，保留与迁移有小至中等收益，同时增加学习时间 | HTML 的步进控件实际允许前进和回退；TTS 文字分段配手动暂停提示，空行本身不算暂停控制 |

这些证据限定交互与伴读的设计选择，不把某份研究推广成适用于所有学习者的固定模板。
需要判断活动安排或修改学习效果表述时，先读 `learning-evidence.md`。

#### TTS 适配，写给耳朵

- 纯文本 `.txt`：没有 Markdown 记号、没有表格、没有嵌套括号、没有网址。
  段落之间空一行，TTS 把空行读成呼吸。
- 句子写短，一句话一个意思。
- 公式念成人话：`∫₂¹⁰ (s−2)(10−s) ds` 念成「从 2 积到 10，被积的是括号 s 减 2，
  乘上括号 10 减 s」。裸 LaTeX 一个不留。
- 记号第一次出现给读法：ⁿCᵣ 念「n 选 r」，σ² 念「sigma squared」，H₀ 念「H nought」。
  HTML 上本来就有记号读法表的，照它念。
- 核心考试词英文照念（binomial、critical region、continuity correction），首次配一遍中文。
- **数字照念。** 这一版跟先修讲稿差得最远的就是这一条：屏幕上有的数值都要念出来，
  念完停一拍，让他的眼睛落到那个数上。
- 口播路标：开章报一句「第几章，讲什么，屏幕上现在是什么」，
  收章报一句「这一章带走一句话」。路标是听觉世界里的页码。

#### 详细度：按学科信息覆盖检查

为当前页面各阶段建立伴读对应：题干限定、定义含义、公式、每步理由、图形关系、反馈与例题都能找到对应片段。英文重复题面与纯控件标签不用重复朗读。运行时由 JSON 生成的参考解答和卡片背面同样进入覆盖清单。

用覆盖与衔接判断完整性，不规定伴读与屏幕字符数的固定倍率。重复解释同一信息不增加深度；公式念成完整语句时长度自然变化。两个轨道合起来覆盖全部教学内容，首次作答轨不含尚未揭示的参考答案。

#### 动笔前先整理 HTML 与活动数据，列一张走位单

大文件先剥成结构清单再动笔（python 的 html.parser 去掉 style 与 script，
标题层级、块的类名、表格的行数都留着当骨架），再把课程 JSON 里的活动题面、反馈、
翻卡背面与开放题参考加回原位置。走位单一行一块，按页面顺序编号，
每行记录：**块的类型 / 屏幕位置 / 学科内容 / 活动 ID 与可见阶段 / 对应讲稿轨道与段落**。
走位单列完，讲稿的骨架就长好了。漏讲几乎都是从「没剥全」开始的。

#### 交付前自查五样

1. **顺序**：走位单从头到尾点一遍，讲稿的段落顺序跟它一一对得上。
2. **覆盖**：每一块都有对应的段落；下半按小问编号点一遍，缺一段补一段。
3. **详细度**：随机挑五处推导与三张表逐行核对，屏幕上有几行，讲稿里就有几句。
4. **带路话**：每一块的第一句都落在看得见的特征上，「上表」「前面那张」这类指代一个不留；块之内不报行号、不报栏名。
   搜一遍「第 N 行」「内容：」「凭什么：」「表头」「中文题面」「英文原题」「左栏」「右栏」，
   块内出现就是滑到讲版面了；再搜一遍成句的英文，题面照读的那种要删掉。
5. **能不能听**：挑三段出声读，每句问一遍「只听一次，跟得上吗」；
   再搜一遍裸 LaTeX 与 Markdown 记号，一个不留。
   逐项检查活动的首次作答轨没有参考答案；题目、暂停提示、主动揭示后的完整解答都有对应段落。
6. **两道后续工序过了没有**：按 §1.86 的读取路由检查适用技能，按 §1.85 记录独立审读或作者自检。
   前五样是讲稿自己的自查，那两节是交付前的工序，依照真实环境执行并记录。

写完按 `respectful-wording` 把开头与结尾各念一遍，想象他就坐在旁边听。

#### 交付

课程数据包含 `tts` 时，组装脚本同时输出 `lesson-listening.txt`、`lesson-answers.txt`
与 `lesson-tts.json`，文件名的 `lesson` 跟随 HTML 主文件名。前两份是首次作答伴读与参考答案伴读，
后一份保存完整分段对应；回复提供各份文件。题目尚未作答时，使用首次作答伴读。
普通非互动讲解的单轨文字仍可使用 `-讲解稿.txt`。现有同步与归档流程只在本次任务采用相应存储位置时执行。

#### 他说别的话的时候，两条退路

| 他说的 | 走哪一套 |
|---|---|
| 「先听后读」「预习版」「听个大概」 | 回到 2026-08-27 的先修讲稿：讲机制、打比喻、几乎零计算，覆盖整份 HTML，后缀 `-先修讲稿.txt` |
| 「念原文」「逐字版」「完整答案朗读版」 | 公式念出来、表格一句一条、指代换成耳朵跟得上的说法；包含答案的整轨标为参考答案伴读，不当作首次作答轨 |

#### 这一段什么时候失效

输入不是结构化的讲解 HTML（纯清单页、纯答案页）的时候，带路话失去素材，
改成按内容顺序如实转述，详细度地板照旧。
他不看着屏幕听的时候（走路、通勤），带路话与闭眼段退场，回到先修讲稿那一套。
TTS 引擎的读法变了（中英混读、数字读法），读法那几条跟着修，别的照旧。
