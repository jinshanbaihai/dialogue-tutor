# 检查产出中的具体断点

既有课程曾出现正确答案掩盖中间错误、题面条件遗漏、页面有“交互”字样却没有作答动作。因此交付检查分别核对数学内容、实际运行和读者能否沿依据推导。

## 作者检查

先依据用户原始要求与模式核对范围，逐项查题面、公式、前提与作答反馈。再阅读适用的 `writing-style`、`respectful-wording`，逐项修改实际出现的文风问题。对占位符、内部矛盾、任务范围和歧义自查一次，发现即修改。HTML 的界面检查参照 `emil-design-eng` 与 `apple-design`，实际新增动效参照 `animate`；数学动画读取所用版本的 `manim` 指南。

本技能修改时读取 `skill-creator`、`obra-superpowers` 中 writing-skills、requesting-code-review、receiving-code-review、verification-before-completion 等当前适用部分。先观察已有失败，再选择形式：输出形状错误使用正面配方；漏项使用必填槽位；条件变化使用可观察触发；跳过已知要求使用具体禁令。不要把完整工程流程重复粘贴进核心入口。

## 独立审读与修正

复杂 HTML 或重大技能修改采用独立子代理。评审者只接收原始需求、产物路径、允许使用的前提、评审范围与输出格式，不接收作者推理历史，不继续派发子代理。让评审者从没有领域背景的读者位置核查，禁止评审者用额外知识补齐正文。

输出先写有证据的 Strengths，再按 Critical / Important / Minor 报告。每项附具体原句或步骤、已经建立的前提、尝试的推导、缺少的依据或实际操作结果。泛泛的“看不懂”和“已完成”都不作为验证证据；未检查的范围明确记录。

逐条完整阅读意见，用自己的话复述，回到产物和原始依据核对，判断本任务是否成立。成立的逐项修改并检查，不成立的给出具体反驳。复审仅列出原 Critical / Important 和对应改动，不重复审读无关部分。最多五轮处理同一问题；到顶仍有余项时记录裁定及理由。将轮次、原意见、采纳/驳回、原因与复查证据写入作者记录，供用户复核。

逐行解释出现缺口时在原来相邻步骤之间补出必要步骤，并让评审者复算；将对学习有用的追问与解释放到对应位置的“预备解释”，评审过程不进入学习正文。保持独立审读、模拟前向使用和真实学生测试的证据区别。

## 技能前向使用

为重大技能修改准备一个当前请求可以代表的新任务，让独立执行者只凭技能及原始材料生成产物。不给执行者预期答案、怀疑缺陷或修复方案。产物保存在隔离位置，检查能否根据技能正确选择模型、逐行讲清、生成实际交互与读题。修复观察到的遗漏后只复查相关要求，不以固定大量重复试验增加成本。

## 实际运行检查

课程生成后打开浏览器，覆盖本次采用的活动类型：正确/错误提交、提示、主动揭示、重试、跳过，卡片切换，推导前后与完整过程，模型边界与重置。检查笔记、书签、导入导出及刷新恢复；这些动作保留现有证据语义。

读题检查播放内容、1.5×、真实声音标签、暂停/继续/停止/重播、换卡与换步骤停止旧内容，以及答案分离。浏览器没有语音服务时区分“用替身验证控制逻辑”和“实际听到音频”，只报告执行过的范围。

对桌面和手机窄屏检查实际截图，核对公式排版、模型标签、换色加粗、阅读层级、键盘焦点和减少动效。已有仓库测试和组装、打包命令按项目要求执行。技能 frontmatter、引用路径与发布包内容同步核实。测试输出、产物与修改差异共同支持结论，单独的成功回执不足以支持交付声明。
