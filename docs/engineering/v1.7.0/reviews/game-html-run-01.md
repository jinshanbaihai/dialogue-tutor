本轮重新运行原有15条游戏探针，并增加6条定点探针。21条均完成观察、无捕获到的脚本异常；“完成观察”不表示21条产品行为全部通过，探针明确复现了下列缺陷。使用 JSDOM 操作交付 HTML、受控时钟和原探针的受控随机序列，不改课件或技能。DOM 状态不构成真实浏览器视觉证据；受控到期不构成真人延迟保持或持续投入效果。

## 优点

1. **开场选择确实改变后续数学对象。** `sampling-lab` 先保存和冻结预测，再揭示枚举。初态无图表和理论结果；改变放回条件会把默认9条有序路径改为6条，新一轮保留前轮条件和预测。手选路径与随机抽样分开，一份随机样本只给统计量频数加1，`n` 与 `B` 没有混用。
2. **具备可执行的递进和修复。** 完整例题 `{2,8}` → 补全 `{1,3,4}` 的 `2/9` → 独立门槛题 `{0,4,10}` 的 `5/9` → 无放回 → 同值个体，增加的是路径、事件、机制或标签判断。数值错误的说明提供具体检查，不假装知道学习者的思考过程。
3. **自由导航与支持不惩罚学习者。** 未预测明确没有原预测；跳题不计答错，并能进入具名例题。提示后答对仍保留辅助标识，推荐的另一题有空白输入、没有提前揭示答案。
4. **大多数收束证据与回访行为可信。** 客观独立、辅助、自评、未作答分别呈现；没有仅因进入最后场景而宣布整章掌握。实际挑战与复习入口均可到达，已做过的挑战标为返回已有作答。真正复习入口收起旧输入和答案、保留历史；未完成草稿和待自评原答保持原样。

## Important

### GR1：结尾把“自动揭示”归因为学习者已经完成映射与归组

**位置。** `evidence-close` 的 `[data-close-story]`；`lesson.json` 中该活动脚本的 `lab.revealedAt` 分支。该条件只证明点击过揭示或直接观察。

**可复现输入。** 空记录进入 `sampling-lab`，只点一次“不预测，直接观察”，随后导航至 `evidence-close`。定点探针 F1 也测试了“选 `centre` → 冻结 → 揭示 → 结尾”，没有手选路径或模拟。

**实际输出。** “你已经在实验中把一份样本映射为一个均值，再把同值的路径合并。”同时，状态为 `simulation.B=0`、`selectedPath=0`（初始值）、`attempts=[]`；跳过路径还明确 `prediction=null`。映射与合并由程序自动展示，本次未收集学习者执行这些过程的证据。

**影响与裁定。** 这会让完成感脱离本人实际行动，也与同页“参与或查阅，尚无作答证据”冲突。不是要求每个图示都必须评分，而是要求反馈只描述已有证据。属于 H3 的虚构行动历史及 H6 的未解决 Important，因此阻止游戏评分达到2。

**先修技能的明确配方。** 在 `references/engagement-and-narrative.md` 的收束规则加入“文案主语—证据字段”对应要求：`revealedAt` 只能支持“你查看了／页面展示了”；手选路径事件只能支持“你定位了某样本”；独立映射、归组正确的表述必须有相应提交或过程记录。默认索引、图表自动生成、进入活动不能充当过程证据。无过程证据时用中性关系说明，再给一次真实应用题。将本例的最小操作反例写入 `references/expert-review.md` 或现有验证配方。无需为了修文案添加积分、强制点击或无意义交互。

### GR2：导入较早状态后，预测组件漏掉本会话已经发生的参考接触

**位置。** `sampling-lab` 自定义脚本的 `restore()`、冻结动作以及 `[data-lab-reference]`、`[data-lab-comparison]`。教育评委先报告此边界，本评委以定点探针 F3 独立复现。

**可复现输入。** 冷启动导出 → 打开 `dt-explanation-opening-scene` 全解并等待 `toggle` 被处理 → 使用公共 `importState` 导入刚才的冷启动记录 → 选 `centre` → 冻结 → 揭示。

**实际状态和输出。** 导入前，自定义 `referenceViewed=true`，运行库 `activities['sampling-lab'].exposure.reference=true`。导入后，运行库仍保留该接触，全解也仍打开；旧自定义探索状态却恢复为空。新提交随后写出 `referenceViewed=false`、`predictionHadReference=false`。页面先称“实验结果尚由你的操作揭示”，揭示后的比较也不再说明提交前已看参考。

**影响与裁定。** 保存／导入没有真正撤销学习者已接触的答案，自定义反馈却丢失这段事实。此处没有把探索直接升级为客观通过，但预测的辅助身份已不可信，违反 H3、H4 的接触记录要求，属于 Important。缺陷与下文已排除的收束刷新问题不同。

**先修技能的明确配方。** 在 `references/interactive-html.md` 与参与动机参考中明确：`dt:restore.detail.state` 只包含当前活动的 `exploration`，不是完整活动状态；恢复及冻结前要另从 `DialogueTutor.instance.getState().activities[id].exposure` 读取运行库保留的接触证据，并检查已经打开的关联全解。旧存档不能清除本会话已经发生的接触；组件当前的接触状态和原预测时点的不可变快照应分开。预测先冻结、后来才查全解时，保持原快照；先查全解再预测时，准确标出辅助。补验这两种顺序及“查全解→导入旧存档→预测”，不要通过关闭界面来伪装没有看过答案。

## Minor

### MR1：等概率结果仍要求解释“这个差异”

**位置与输入。** `sampling-lab`，`n=1`，有放回或无放回，预测 `equal`，冻结后揭示。原探针与定点 F2 均复现。

**实际输出。** 正确给出 `P(均值=3)=1/3`、`P(均值=1)=1/3`，随后说“结果与本轮判断一致。检查下方路径，找出这个差异怎样形成。”这里没有概率差异。

**裁定与先修技能配方。** 数值、操作和下一任务不受阻，但发现反馈指向不存在的差异，Minor 未关闭。技能应要求比较型反馈同时依据“是否符合预测”与“实际关系为相等／较大／较小”，不是只按预测对错套句。相等时邀请解释为什么一样常见，非相等时才解释差异，并把允许参数的等值情形加入成品反馈验收。下一轮需修复，不以平均分或一般免责声明抵消。

## 已排除的候选故障

**“`dt:restore` 被 `activityId` 过滤，因此收束导入后不刷新”未成立。** 运行库 `notifyCustomRestore()` 对每个已挂载的 `interactive` 分别发出 `{activityId, state: exploration}`，其中包含 `evidence-close`。

原探针在已位于结尾时连续导入空／有独立记录的存档；定点 F4 另外点击导入后的实际复习按钮。两者都未通过额外导航强制刷新收束：文案分别显示无证据／独立核对记录，复习按钮实际分别进入 `return-recall`／`mean-independent`。恢复事件顺序中可见 `sampling-lab`、`evidence-close`。因此不要求为这个假设修改收束事件过滤，也不把它计作风险或扣分项。
