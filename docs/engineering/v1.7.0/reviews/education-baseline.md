# 教育学专家独立基线评审：dialogue-tutor 1.6.0

评审日期：2026-09-07。评审对象根目录：`/workspace/scratch/b4c4b2db70f4/baseline/dialogue-tutor/`。下文文件名和行号均以此只读基线为准。

我的结论是：1.6.0 已经建立可信的作答记录基础，但课程组织仍是“讲解完成后嵌入活动”。这不能直接满足本次“交互＞可视化＞文字”的结构性要求。我建议保留完整解释、模式边界和证据纪律，重建生成入口与课程编排，而不继续给旧长文加规则。

我已审核 `/workspace/scratch/b4c4b2db70f4/reviews/implementation-proposal.md`：**通过进入实现**。这是对实施结构的批准，尚未批准候选技能或最终 HTML；后两者须分别审读与实际操作。

本轮我阅读了 SKILL.md 全文（2230 行、162264 字节）、六份 references、builder、runtime、CSS、课程 JSON，以及示例 HTML 的全部教学文本和相关结构。并执行了只读课程验证、目标活动映射、插入位置解析，以及两个隔离的 runtime 状态操作。没有修改技能，没有生成课程 HTML，没有把模拟数据写入实际学习记录，也没有获得真人学习成效数据。本报告中的“观察”指文件或隔离代码操作；对学习后果的判断均为设计推论。

## Strengths：我会明确保留的现有优点

1. **完整解释具有具体的内容责任。** `SKILL.md §1.6、§1.9、§1.95` 要求条件、记号、方法、依据、推导和原题限定词可追溯。这比泛称“解释清楚”更可检验。`examples/s2-interactive.json` 的 `q2a-answer`（约 L590–646）保存归一化证明原答，评价要点承认代换积分等合法异解，是值得保留的设计。
2. **区分“看过”“答过”和“会了”。** `SKILL.md L93–95、§2–§3` 与 `learning-evidence.md` 已经拒绝把追问数量、操作次数和一次正确当成长期掌握。runtime L349–368 分别汇总客观核对、自评、参与；L273–278 的开放题自评不会换成客观评分。我的改造不应把这些边界抹平。
3. **作答顺序及求助权利已经落实。** runtime L233–331 保存提交时原答，区分提示、揭示、重试与跳过；L658–666 还检查原题完整解答是否提前打开。`SKILL.md L1084–1093` 明确允许真实学习者求助、跳过和返回，不要求先证明自己困惑才放行。
4. **内容范围尊重当前任务。** `bgct / bbct / olct / onct` 的范围差别、板书未覆盖作业仍须补齐、考纲和公式条件的核对，是用户工作流的一部分，不能因为界面重设计而丢失。
5. **参考资料的证据边界有所改进。** `deeptutor-provenance.md` 把源码、截图、DOM 检查和实际服务端行为分开；`learning-evidence.md` 明确论文没有测试本次 HTML。它也保留了对旧研究转述的纠正。我认可这种可核查性。
6. **可回查和伴读已受重视。** `SKILL.md §1.65 六` 的中文伴读、考试术语、作答轨和答案轨分开，以及 runtime 的草稿、笔记、书签、导入导出与复习入口，为自主学习提供了实际支持。新结构应让这些支持更容易使用。

## Critical

### C1：现行最高规则仍把文字讲解放在教学动作之前

**位置。** `SKILL.md L35–39` 要求默认先把讲解写足；L70 明写先保留讲解再穿插操作；L694–706 固定上下两半；L728–769 固定七幕顺序；L1747–1751 拿不准时继续展开。`interactive-html.md L33–41` 再次维持七幕和两半。

**观察实例。** 我用 builder 的实际 selector 解析了示例：`cdf-density-steps` 被放在 `s2-source.html L255–269` 的完整推导表之后；`uniform-density-steps` 被放在 L643–661 的完整推导表之后；`linear-density-explore` 在 L512–540 的已标出答案例图之后。首次 CDF 回忆卡也在 L226–242 的定义及差值表之后。这里确实是先呈现结论、再提供控制相同结论的操作，而非任务驱动的首次建构。

**我的判断。** 这不是“活动数量不够”，而是入口合同、正文模型和示范输出共同规定了旧顺序。把完整讲解全部提前展示，会减少预测、选择和建构的空间；本轮没有真人数据，因此我不声称它已造成某个学生失败。

**结构修改。** 最高规则改为“确定学习目标及可观察证据→设计有意义的学习动作→用图形显现关系→按需给出完整解释”。默认主线按任务场景推进，七幕的有用内容改成机制、历史、边界等参考内容，不再规定必经七屏。每个目标的完整例题、公式条件、推导与原题解答仍全部可查。对于缺少先备知识的人，立即提供具名例题或先备说明；交互先行不要求无指导猜难题。

**验收。** 从干净课程状态开始，第一次学习动作出现前只需阅读该动作必需的情境、记号和条件；不先展示该动作待判断的结论。至少一条核心路径由“先尝试/预测→观察→解释/应用”驱动。首屏出现按钮但按钮只负责打开长文，不算通过。

### C2：目标已经写出，目标所需的学习证据却没有被保证

**位置。** `examples/s2-interactive.json L8–49` 的 objectives；builder L76–101 只验证活动所指目标存在；runtime L963–973 把目标显示为活动链接。没有检查目标反过来是否得到合适的证据。

**观察实例。** 基线 JSON 通过 `validate_lesson`。其中 `cdf-relation` 是“解释累计概率、密度面积与区间概率的对应关系”，却只对应翻卡、步进和探索；`uniform-model` 是解释支持区间的影响，却只对应步进和探索。二者没有独立的解释或应用题。程序实测向复制的数据追加一个完全没有活动的概念目标，验证器仍然通过。这个反例仅在内存中执行。

**我的判断。** 不把滑杆记成掌握是正确的，但如果课程不安排别的证据，便永远无法回答“这个概念是否学会”。已有证据标签只能避免误报，不能补上缺失的评估任务。

**结构修改。** 在制作正文前要求目标→证据→活动→分支→完整解释索引的蓝图。目标写成行为，例如“给出一次样本，并解释它怎样贡献抽样分布中的一个值”。每个核心概念目标至少对应一次辨析后解释或新情境应用；每个程序目标对应一次真实产出的计算/分布构造。记录 `example / completion / independent / transfer / delayed-same-item` 等任务身份，避免把同题重试改名为迁移。

**验收。** 无活动目标、解释目标仅有翻卡、应用目标仅有点击时须在编排检查中失败。开放题仍可自评，但汇总必须说清它只有自评证据，不能升级为客观独立通过。

## Important

### I1：预测与自我解释停留在指令文字，缺少可观察产出

**位置。** `s2-interactive.json` 的 `linear-density-explore`（L239–277）与 `uniform-explore`（L410–449）；runtime L714–732、L761–811、L321–325。

**观察实例。** 两个探索都要求“先预测”；15 个活动的配置没有预测字段。内置探索保存端点与操作次数，未保存预测或结果比较。步进提示要求先说明，但隔离测试可以直接跳到最后一步，得到 `stepIndex:5, participated:true, draft:"", attempts:[]`。运行时如实不记正确，这是优点；“解释是否发生”仍不可见。

**修改与验收。** 每次核心探索先让学生留下一个简短预测（选择、数值、标记或一句理由），提交后冻结；再操作，再把原预测与结果并排比较，提供修改解释的入口。预测不出来可看示例或跳过。普通阅读步进继续允许自由跳转；需要生成推导证据时另做步骤补全或依据选择，不能用下一步按钮替代。验收检查刷新后仍能区分原预测、观察状态和修订解释。ICAP 的“Interactive”有共同建构含义，网页有控件不自动属于最高认知参与等级，见 R1。

### I2：完整例题与独立练习之间缺少渐隐支持

**位置。** `SKILL.md L787–838、L1372–1489` 反复要求例题和每个作业小问六样全额、篇幅同量级；`interactive-html.md` 的 steps 只有 `{title,bodyHtml}`；示例 15 个活动没有步骤补全任务。

**观察实例。** 源 HTML 的例题完整展示所有步骤；原题活动要么选/填最终结果，要么一次输入整段证明。两者之间没有只承担部分推导责任的任务。`q1a-answer` 将原来 `specify fully` 的写出函数任务改成选择已有完整写法；它能检查辨认，不能直接证明学生能自己写出。

**修改与验收。** 提供“完整示范→不同题的缺步补全→独立新题”，按学生表现推荐经过或跳过支架；每一步完整解释均能主动查阅。相同答案刚被揭示后的补全标记为辅助练习；独立新题须使用未直接展示过的题目。原题命令动词保持不变，选择型支架明确标作支架，最终仍保留原要求对应的产出。R2 支持渐隐的近迁移用途，不能据此保证远迁移。

### I3：缺少“已学过”和“本次能用”的先备诊断区分

**位置。** `SKILL.md L141–153` 拿不准就视作不知道、讲后放入雪球；`references/考纲与考试局.md L27–37` 把 S1 全部内容列为可直接使用的前置范围；`SKILL.md §0` 的最终独立完成判据主要依赖作者拆链。

**观察实例。** 示例课程没有单独的先备诊断。source L651–652 的均匀性推导直接以“柯西函数方程＋单调”推出线性；作者给了名字，却没建立为什么这个前提对本读者可用。范围允许使用某知识，与这个人当前能够调用它，是两回事。

**修改与验收。** 新章节只检测本次实际用到的少量前提；将状态写为“未检查、当前任务可用、需要支持”，不要由讲过推断已会。CH6 可检查平均值、简单联合概率和分布图读法。若未通过，提供对应小例子后回到同一任务，不要求重读整个 S1。先备诊断是可选择的推荐路径，不是阻止查阅的门禁。

### I4：错误反馈主要追加解释或同题重试，没有具体后续任务

**位置。** runtime L674–710 的选择反馈、`remediation` 和 retry；L936–973 的导航；课程 JSON 全部活动。

**观察实例。** `density-concept-check` 的“密度过高”错误与“单点有正概率”错误得到不同文字反馈，但后续都是同一个文本补充、参考和同题重试。`remediation` 没有目标活动 ID；活动图也没有 incorrect/assisted/correct/skipped 的后继。

**修改与验收。** 每个高价值错误至少有一个具名补救动作，如“把两块不同宽度矩形归一化”或 CH6 的“把样本结果按统计量合并”。辅助后正确推荐另一道新题，独立正确推荐下一目标或迁移，跳过保留返回入口。路径是建议，不以关闭导航惩罚错误。验收要真的做一次错误、提示后正确、独立正确和跳过，核对推荐任务与触发原因一致；开放题自评不得触发客观独立通过分支。

### I5：新组件已修正的解释没有同步到完整讲解

**位置。** `examples/s2-source.html L1428–1431` 与 `s2-interactive.json L707–716` 的 Q2(c)；`SKILL.md §0.5` 允许沿用完整 base HTML 注入活动。

**观察实例。** source 全解仍说任何关于某点对称的密度，期望都在该点；JSON 的解析已补上本题有限支持、期望存在的条件。学习者走两个解释入口读到的适用范围不一致。source L265–290 还存在把单点结论往后引用、后文再用同一积分关系说明单点的依赖问题；此处已转交数学评委核算，不以我的教育身份替代数学结论。

**修改与验收。** 以概念、题目、解答为有身份的内容对象，维护同一个规范版本；活动反馈可以简短，但必须指向同版完整解释。数学修正应覆盖题面、提示、图、参考、TTS 的所有出现处。保留旧版本作为档案，不把档案中的错误继续作为现行全解。验收按知识断言而不只按字符串/锚点检查一致性。

### I6：对字数、等号行数和模拟审读的硬要求，仍有替代学习判断的倾向

**位置。** `SKILL.md L721–726、L831–838、L1108–1121、L1486–1489、§1.11`；`references/数学的冲突读法.md L8–16` 要每一行六样都出现在稿子里。

**观察实例。** 当前仍以“讲不清就还太短”“下半不比上半短”“每行依据数量相等”检查内容，并在跨领域记录中以成品能生成称作结构迁移证据。样章声称每个等号单独一行，但 L425、L692、L694、L1074–1076 等实际仍有多个等号。这说明机械指标并没有稳定控制它想保护的推理完整性。

**修改与验收。** 我保留“所有关键等号可追溯”和“可查到每一步”的内容标准，删除固定篇幅比较与强制七幕顺序作为当前主线合格条件。用目标/前提/推导/误解/迁移覆盖矩阵代替。模拟学生审读仍查缺少的前提、错误和可理解性，但必须报告覆盖与复算，不能输出“我懂了”就当真实学习效果。历史、异说和学术背景按模式保留在明确的可选阅读，不用强制名人批评挤占首轮任务。

## Minor

### M1：每个活动重复显示工具及实现出处，教学主次可再收紧

**位置与观察。** runtime L878–909 给每个活动创建收藏、复制上下文、笔记和“交互来源 · DeepTutor”；L955–985 的学习面板另有状态与调度说明。它们是真功能，但与当前数学动作同时呈现的入口很多。

**修改与验收。** 主动作保留清晰的视觉优先级，收藏/笔记/出处归入可展开学习工具；源码追溯仍可查。检查窄屏首次任务时能否一眼辨认“现在要做什么”，不以全部控件同时可见为完整性标准。此处只是布局风险；我本轮未作浏览器可用性测试。

### M2：历史修补与现行合同混排，后续作者难辨规则优先级

**位置与观察。** SKILL.md 从 L2010 起有约 220 行完整历史记录；§1.65 与 §1.85–§1.86 内还保留大量历史原话与外部技能调用说明。虽然 §9 已明确历史不覆盖现行，入口仍需读 162KB 才理解哪些要求已被替代。

**修改与验收。** 当前合同只保留适用规则、路由和验收；历史留 git 或明确档案，不再作为必读教学规范引用。不要将 162KB 整体搬成另一个“现行参考”。随机抽一个新任务，作者能从入口找到唯一的模式、教学流程和操作规格，不需要解决不同年代条文冲突。

## 我建议的技能组织

| 文件/模块 | 当前职责 | 不应继续承担的职责 |
| --- | --- | --- |
| `SKILL.md` | 触发、模式路由、交互优先目标、先做蓝图、生成与验收的顺序 | 历史全文、冗长正反例、重复的文风立法 |
| `teaching-design.md` | 目标证据映射、先备诊断、预测观察解释、渐隐、反馈分支、迁移和延迟检验 | 精确 CSS、来源证明、固定每段按钮配额 |
| `modes-and-explanations.md` | bgct/bbct/olct/onct 范围，原题保真、公式条件、全解索引、TTS 可见阶段 | 强制全员从头读完的七幕长文流程 |
| `visual-design.md` | 图形的教学用途、邻近标注、对比、字号、键盘、减少动效和恢复位置 | 以主题色或动画数量推断学习效果 |
| `interactive-html.md` | 唯一 schema/API 合同、活动与推荐路线、保存恢复、提交揭示语义 | 与教学文件重复定义不同版本流程 |
| `learning-evidence.md` | 研究对象、任务、结论、边界、采用决策；旧误引修正继续保留 | 假设所有高中生具有同一认知特征 |
| `deeptutor-provenance.md` | 固定来源与实现迁移可追溯性 | 限定课程只能照抄某张示例页的布局 |
| 学科参考 | 官方考纲/教材版本、原题和评分依据、术语 | 把考纲允许使用当作个人已掌握 |

我要求当前规则单一来源；其余文件通过引用使用，不重复抄同一张模式表。改变 schema 时保持 1.6.0 课程可读，不覆盖旧草稿、原答、笔记、书签、日期或课程身份。内容语义变化应产生新 revision，旧 revision 的记录留存；不要静默把旧题成绩套给新题。

## 我要求逐项迁移的用户约束

| 旧要求 | 新结构中的保留方式 |
| --- | --- |
| 完全理解，不能只罗列公式 | 每个核心对象有机制解释、条件、逐步可查推导，以及相应解释/应用任务 |
| bgct 的完整背景与独立例题 | 全部内容可查；主线按任务组织；背景不强迫在操作前读完 |
| bbct 板书和未覆盖作业均处理 | 建立板书/作业覆盖表，记号优先一致，缺字明确标注，考纲补齐遗漏范围 |
| olct/onct 只做当前题与必要定义公式 | 不引入背景章节、历史争论或考纲外理论 |
| 原题限定词不缺 | 原卷→中英总题面→小问的约束链，保留随机、放回层级、恰好/至少/只用、单位/范围/精度/分值；额外解释单列 |
| 每小问全解与依据可查 | 题面、方法条件、依据、计算、答案与得分依据各有位置；改成折叠不等于删去 |

## CH6 的可实施课程流程

Pearson 官方 2019 年 Statistics 2 样章目录明确：第六章是 **Sampling and sampling distributions**，包括 6.1 populations and samples、6.2 statistic、6.3 sampling distribution；hypothesis testing 是第七章。我只用这个官方目录确认章节边界，未将网络上其他版本的编号混入。genui{"citation":{"ref":"turn935278view2"}}

下表是我的教学设计方案，不声称已经在学习者身上验证。时间可由学习者控制，任务允许暂停；课程开头不要求先读完整长文。

| 阶段 | 学习者实际做什么 | 图形与解释承担什么 | 收集的证据/下一步 |
| --- | --- | --- | --- |
| 入口和先备检查 | 对一个小型总体选取样本，算一次平均值，辨认分布中的一个点/柱 | 只给当前需要的对象、单位与抽取规则 | 记录原选与理由；不会时先看具名小例子，再返回 |
| 总体、样本、普查 | 在两个具体调查情境中指出总体、抽样单位、样本；选择 census 或 sample 并说明代价 | 同一组带身份的对象显示哪些被观察；避免把“样本看起来一样”当代表性证明 | 分类与理由，不只术语背诵；错误回到对象标注 |
| statistic | 固定一份观测，判断样本均值、最大值和含未知总体参数的式子能否只从样本算出；再换一份样本 | 观测→运算→一个统计量值对应；定义及 only 的含义就地可查 | 选择加数值或解释；区分统计量这个规则和一次得到的值 |
| 构造抽样分布 | 对总体值 0、2、4，按有放回 n=2 的规定先预测哪种均值较常见；逐对列出 9 个有序结果，并按均值合并 | 每一对样本贡献一个统计量值；总体图、一次样本与许多统计量值的图明确分开 | 保存原预测、样本对分组和分布表；合并后概率应为 1/9、2/9、3/9、2/9、1/9 |
| 改变取样协议 | 改为无放回，先指出哪些结果消失，再重算统计量的分布 | 条件改变时联动样本空间与权重，解释何时等可能 | 6 个有序结果合成均值 1、2、3，各 1/3；解释为什么结果集合相同不等于概率相同 |
| 连接模拟与精确分布 | 一次抽一组，计算并落一个统计量点；再做多次并比较相对频率与精确表 | 画面区分每组样本量 n 与重复次数；显示随机模拟只是近似 | 学生解释“一根柱子计数什么”；增加重复次数不当作证明，也不假称改变了理论分布 |
| 渐隐练习 | 看一个完整例题；在另一题中补缺失的分组/概率；最后独立写新题分布 | 可查所有步骤，提示逐级提供 | 辅助后正确推荐新题；数值表与方法说明分别核对 |
| 迁移与离开前检查 | 在新的情境或不同统计量下完成分布，并解释结果如何随抽样规则变动 | 仅保留题面必要数据，按需查全解 | 保留首次产出；概念、程序、迁移分别呈现，不宣布“全章掌握” |
| 延迟回顾 | 从既有复习入口重新提取定义/关键过程，再做一题新应用 | 到期先显示问题，收起旧答案 | 同题保留与新题迁移分开；沿用公开间隔默认，不称个人最优 |

若正文计划引入重复数值、非等概率总体或别的统计量，先明确对象身份及样本概率，不允许“统计量取值有几种就均分概率”的隐含规则。CH6 主线不因模拟图变得好看就扩张到第七章或超出当前考纲的理论。

## 与游戏策划合作时，我会坚持的教学接口

我支持游戏策划决定情境、任务命名、视觉反馈和叙事节奏；教育设计先给出每项任务的数学动作、可观察原答、错误类型与解释入口。适合 CH6 的主动作是选取、抽样、算一个统计量、按值归组、比较条件和修正分布。奖励应回应有依据的发现或完成任务，不能由随机抽到“好结果”或点击速度代替数学判断。

需要一次抽样过程的可见性时，先演示一轮，再允许批量模拟与跳过动画。剧情不得偷换有放回/无放回、均匀/非均匀或重复次数；若叙事引入“抽取工具”的限制，要与题目条件相符。每次关键反馈应帮助学生知道自己的模型哪一步需要调整，不以扣生命、连胜清零或强制重读增加无关压力。所有任务保留键盘可用、跳过、返回和主动查全解。
