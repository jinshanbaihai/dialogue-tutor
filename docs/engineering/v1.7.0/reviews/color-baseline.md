# dialogue-tutor 1.6.0 色彩与视觉设计独立评审

评审者立场：我从美术构图、摄影明暗关系与数学界面视觉设计三个角度评审。我不借用任何真实人物的身份。此次判断针对基线源码和仓库已有截图；候选技能与新生成页面需要另行审核。

审查范围：`baseline/dialogue-tutor/SKILL.md`、`references/interactive-html.md`、`assets/interactive/lesson-runtime.css`、`assets/interactive/lesson-runtime.js`、`scripts/build_lesson.py`、`examples/s2-source.html`、`examples/s2-interactive.json`。我还查看了 `repo/docs/images/hero.png`、`dark.png`、`figure-density-cdf.png` 与 `act-derivation.png`；这些既有截图能证明原视觉方向，不作为新版本实际渲染已经通过的证据。

我的结论是：现版有认真制作的教材底子，但没有形成清晰的学习工具视觉系统。单个颜色大多不刺眼，整页却显得发灰、陈旧、平铺；活动进入正文后，又叠加了第二套色调和边框。用户所说的“丑”，我理解为视觉重心不明确、色彩身份混乱和界面密度缺乏节奏共同造成的体验，不能只替换一个背景色解决。

## 我认为值得保留的优点

1. **数学对象已经有可视化基础。** `s2-source.html` 的四幅图确实说明密度面积、CDF 高度差、均匀分布和等长区间；它们不是装饰插图。`figure-density-cdf.png` 中左右图的轴线、区间端点与高度差可以建立对应。新设计应该把这种关系提升为当前舞台的主体。
2. **现有颜色数量受控。** 原样章没有给每一段分配一个随机颜色，正文的深色和浅底也有较高可读性。运行组件的浅色正文 `#302e28`、辅助文字 `#706b60` 与 `#fffdf7` 并非天然不可读；辅助文字的计算对比度约为 5.21:1。我的批评不把“暖色”简单等同于“低质量”。
3. **运行组件已具备可收拢的基础。** `lesson-runtime.css` 把样式放在 `.dt-activity` 与 `.dt-study` 下，已有变量、焦点轮廓和减少动效规则。这使统一主题有明确落点。提示、参考、自评、客观正确的文字身份已有区分，重设计不应删掉这些证据差异。
4. **大块内容没有靠眩目效果维持注意力。** 阴影很轻，动画有限；这适合长时间观察公式。我会保留克制的动效，但以更清楚的明暗层次和操作状态补足视觉反馈。

## Critical：我认为会阻碍学习或继续制造劣质成品的问题

### C1. 暗色模式的数学图示没有完成主题适配

`examples/s2-source.html` 第 26 行附近切换了 CSS 变量，但四幅 SVG 仍把函数线写死为 `#8a5a2b`，标注写死为 `#a8442a`，均值写死为 `#2f6f4f`。例如第 297 行附近的密度/CDF 图，以及第 708 行附近的均匀分布图。更严重的是，SVG 的普通 `<text>` 没有设置 `fill`，默认黑色不会因为父级 CSS 的 `color` 改变而自动变成浅色。

我按实际色值计算，暗卡背景 `#1c1a15` 上：

| 图示内容 | 实际前景 | 对比度 | 我的判断 |
| --- | --- | ---: | --- |
| 未设置 fill 的 SVG 标签 | `#000000` | 1.21:1 | 轴名、端点等必要文字几乎消失 |
| 函数线 | `#8a5a2b` | 2.96:1 | 低于必要图形 3:1 的基线 |
| 高度差/面积标注色 | `#a8442a` | 2.92:1 | 图形和小字都不够 |
| 均值标记 | `#2f6f4f` | 2.90:1 | 必要的数学位置弱化 |

`lesson-runtime.css` 第 219 行的第二端点 `#306b7b` 也没有暗色覆盖，在 `#24241f` 上只有 2.61:1。运行时面积色 `#8db0a1` 以 0.38 透明度合成后，在浅底上约为 1.34:1，暗底约为 2.12:1；当面积的左右边界只能靠这块低对比填色辨认时，我不能认为信息表达可靠。

W3C 对普通文字要求至少 4.5:1，对辨识控件与理解图形所必需的非文字信息要求至少 3:1。[1][2] 装饰网格可以很轻，事件端点、CDF 差值、区域边界和坐标文字不能归入装饰。

我的修正要求：所有图形由语义 token 控制；普通 SVG 文字明确使用 `fill: var(--dt-ink)` 或标签 token；浅填充同时配有足够对比的轮廓、纹理或明确端点。浅色和暗色是两套完整曝光方案，不能只换画布后沿用全部颜料。

### C2. 三套色彩系统同时存在，生成路径决定成品长相

| 所在文件 | 画布/卡片 | 主强调色 | 结果 |
| --- | --- | --- | --- |
| `examples/s2-source.html` 第 21–30 行 | 暖纸 `#fbfaf7` / 白卡 | 赭褐 `#8a5a2b` | 旧教材与棕色批注的视觉气质 |
| `assets/interactive/lesson-runtime.css` 第 4–15 行 | 奶白 `#fffdf7` / 米灰 `#f7f3e9` | 灰绿 `#35685c` | 叠进正文的另一套卡片皮肤 |
| `scripts/build_lesson.py` 第 379–382 行 | 米白 `#faf8f2` | 蓝绿 `#215d59` | 新建课程又有另一套底色、文字与宽度 |

我看到的失败不仅是“颜色不统一”。原图的褐色表示函数、标题与链接；运行时绿色又表示函数、提交按钮、选中状态、活动类型和成功反馈。学习者无法通过颜色快速确定眼前是数学对象、可操作元素还是结果状态。暗色时，旧页是偏黄褐的近黑，运行组件变成偏橄榄的灰黑；这一组差异会产生脏灰的印象。

我的修正要求：builder、runtime、样章、SVG 和自定义组件共同读取一套命名和数值确定的主题。生成参考中只允许语义用途，例如“函数”“参数 a”“主动作”，不让每次生成自由发明“好看的绿色”。历史样章应成为同一主题的真实示范，不能继续向生成器展示旧配色。

### C3. 技能仍在鼓励文字优先的视觉构图

`SKILL.md` §0.5 第 71 行附近明确把“先保留完整而准确的讲解”放在目标排序首位。`references/interactive-html.md` 主要规定活动如何穿插正文，却没有规定当前学习动作怎样成为首个视觉焦点。完整性当然要保留，但当前要求是“交互＞可视化＞文字”，这应当改变呈现次序和视觉面积。

原样章首屏由仓库横幅、课程说明、目录、长引导段构成；`hero.png` 里还没有实际操作，学习者已经读完一整层页面说明。JSON 的 15 个活动主要接在表格、静态图或例题后面。builder 对没有 `<header>` 的原样章又把学习记录插到 `main` 最前面。结果是元信息、进度工具和长正文先占据注意力，数学操作来得很晚。

我主张把七幕和六项解释定义为**内容覆盖合同**，同时增加独立的**呈现合同**：进入一个学习单元，先看见当前问题、可操作对象和一个清楚的主要动作；操作后就地看见变化和一句关系说明；完整推导、来历、反例和评分依据在相应位置展开取得。可视化与文字仍需完整建立前提，交互也不能要求学习者使用尚未讲明的知识。

这不是减少讲解，而是给完整讲解安排重心和阅读节奏。我的视觉验收不接受只在长文中插入一个彩色按钮就宣称“交互优先”。

## Important：我认为会显著降低成熟度的问题

### I1. 图在容器内持续缩小，字比辅助说明还小

`lesson-runtime.js` 第 741 行使用 `viewBox="0 0 420 252"`；CSS 第 209 行默认将两幅图并排，第 211 行图字为 15 SVG 单位。样章的 `main` 为 47rem，活动又嵌在 `.act` 中，加上两层水平 padding 后，两列图各约 300.8 CSS px，图中字实际约 **10.74 CSS px**，图题约 11.46px。这个数是按源码尺寸计算的估计，候选版仍要检查浏览器中的真实矩形与缩放。

620px 的 viewport 断点不能感知嵌套后的图容器宽度；在窄桌面或平板尺寸，双列仍会被保留。我建议用容器宽度决定单双列：单图实际宽度不足 380px 就改成单列，或者使用文字不随整张 SVG 缩小的绘制方式。两张同时比较有学习价值时，让舞台突破正文宽度，而非牺牲轴名可读性。必要图中文字实际显示至少 14px；这是本产品的设计标准，不冒称 WCAG 规定了这一字号。

### I2. 大量套框与附属控件占用了数学内容的面积

原样章有 14 个 `.act`，在其内部添加 `.dt-activity`，还会进一步出现闪卡、反馈框、步骤框和指标框。活动的顶部 3px 色条、外边框、阴影和内框反复出现，页面缺少“哪些是舞台、哪些是说明”的区分。JSON 中 15 个活动都由 `createActivityView()` 追加收藏、复制上下文、笔记和来源；第 905–908 行证明这些并非偶尔出现的功能。

我同意把这些功能收拢到每个活动一个“学习工具”入口；记录和导入导出留在课程层。来源信息放入统一说明或工具内，不必每次操作都先经过实现 provenance。保持功能可用，减少重复界面占用。

一屏的视觉面积中，我建议主动作及关联图形占可用主体的大约一半或更多；说明占其后。这个比例用于审稿观察，不做机械的像素合规条款。正文区可用 700–760px，互动舞台可扩到 1040–1120px；段内 padding 通常 20–24px，窄屏 16px。不要把每一小段都装进独立圆角盒子。

### I3. 排版同时传达“厚重文章”和“微小控件”

样章正文 17.5px、行高 1.95，确实从容；但运行组件 `0.96rem` 实际为 15.36px，按钮 `0.8rem` 为 12.8px，类型眉题 `0.69rem` 为 11.04px，说明 `0.78rem` 为 12.48px。`rem` 取根字号，并不取 body 的 17.5px。更大更黑的正文压过更小的操作，恰好强化了文章优先。

我建议使用一致的现代中文无衬线正文与界面字体，数学保留规范数学字体；正文 17–18px，主要控件与题干至少 16px，辅助说明 14–15px，标签 12–13px且只用于不承载主要信息的短词。正文行高 1.65–1.8，公式块独立增加竖向空间。中英文并排采用同一套字号层级，不用过宽字距补救字体混杂。

`act-derivation.png` 的三列表有逐行依据的优势，但全边框长表加浅灰小字会像文献附录。完整表可以保留为展开视图，主舞台显示当前等式、当前依据和相关图上位置；行号成为定位标记，不与数学结论竞争。

### I4. 控件边界和装饰分隔线共用浅灰

`lesson-runtime.css` 第 123 行把输入边界设为 `--dt-line`。浅色 `#dcd5c6` 对 `#fffdf7` 只有 1.44:1，暗色 `#484b3e` 对 `#24241f` 只有 1.75:1。空输入框没有足够清楚的内部底色差，边框承担了识别输入区域的责任，此时不能采用只适合装饰分隔的灰色。[2]

我会把 `line` 与 `control-line` 分开。按钮若有足以表明作用的文字，不是每条边框都必须达到 3:1；不能为了审计把所有分隔线染深。交互区域清楚、文档背景安静，两件事需要不同 token。

### I5. 色彩身份需要跟随变量，而不是跟随组件

运行图的 a、b 端点已经有不同色，但参数滑杆都用一个 accent，CDF 差值也没有稳定地对应事件阴影。原图中“总面积”和“所求面积”又在不同章节改用褐与红。颜色应该是一份数学字典：参数 a 在滑杆标签、图上端点、公式中的 a 和表中 a 都保持一个身份；b 同理。函数用蓝色，另一条比较函数用紫色；事件区域与其概率差用同一个温暖强调色，再增加轮廓或纹理。正确/错误用文字与图标双重标识，不单靠颜色。[3]

## Minor：我会在整体方向稳定后处理的细节

- 所有卡片都有近似圆角与边线，会把不同层级压平。建议舞台 14–16px、控件 8px、内部分组尽量用间距和轻分隔；具体尺寸可随实现调整，原则是只保留少数固定档位。
- `.dt-eyebrow` 的 0.1em 与样章标签的 0.1em 字距在小号中文上显得零碎。我只给短拉丁编号或确有需要的眉题增加少量字距。
- `box-shadow: 0 4px 18px rgb(64 47 23 / 3%)` 在米色上主要增加脏灰，不产生有效前后关系。普通卡片可去掉阴影，浮层才使用中性墨蓝阴影；不要用阴影数量表达教学的重要性。
- 自动跟随系统明暗已经存在，但我建议提供明确的“浅色 / 深色 / 跟随系统”选择并保存偏好。主题偏好不应被表述成医学效果，也不必因为历史备注中出现干眼症就宣称某一种色相具有治疗或保护作用。

## 我批准进入实现的艺术方向：冷白、墨蓝、铜橙

## 我如何把摄影中的色彩关系用于这套界面

我会先做一张只有明暗的构图，再上色。把界面视作一个被布光的静物场景：画布是环境，互动舞台是被照亮的工作面，当前可调参数是小面积暖色主体；解释文字有足够亮度但不抢占主体。先确定这个顺序，才讨论铜橙具体偏红还是偏黄。

浅色主题的层次来自冷灰画布、白色工作面和深墨字；深色主题的层次来自墨蓝画布、稍亮的蓝色工作面与浅色字。暗主题不使用黑上加半透明黑的办法，也不把文字降低到灰黄来制造“柔和”。保留三个稳定亮度层，比加入更多材质和渐变更成熟。

我会把大部分画面保持在低彩度中性色，饱和色集中到当前任务。约 80–90% 中性、8–15% 轻度带色结构、2–5% 强调，可作为第一轮构图草图的检查方法；它不是公式，反馈出现或图形放大时允许变化。判断仍然是：第一次扫视，能否立刻知道当前应看哪里、动哪里、变化在哪里。

我不会通过给每一幕换一种色来制造变化。篇章的节奏应来自大图、小段、当前等式、操作和安静的展开说明交替。颜色承担恒定语义，布局承担节奏，数学关系承担趣味。

## 为让生成器持续产出好看页面，我要求补齐的合同

1. **在 SKILL 开头写明当前优先级。** 把“交互＞可视化＞文字”定义为呈现与注意力的优先级，同时保留数学准确、前提完整和解答可取得的硬要求。不要把完整性与首屏长文绑定。
2. **独立出视觉参考文件。** 例如 `references/visual-system.md`，只维护主题 token、布局、字阶、图形语义、状态与验收；SKILL 用短路由指向它。把历史故事、旧版本配色和过往失败记录移到可选背景，不让生成器同时读取多套现行标准。
3. **建立唯一颜色来源。** builder 外壳、runtime、静态 SVG 与自定义 interactive 一起使用 `--dt-*` token。保留兼容旧变量时，旧变量只能是别名。除了 theme 定义，业务组件不出现新十六进制色值。MathJax/MathML 的公式继承正文色，图标与 SVG 文字有明确 fill。
4. **每个组件必须声明学习状态和显示状态。** 题目未答、已选、已提交正确、待修正、已看提示、参考展开、键盘焦点都给出语义与可见样子。使用文字、图标/边界和颜色，不让“颜色变绿”独自承担解释。
5. **给出两种真实布局范例。** 一种是“参数操作＋两图联动＋当前关系”，另一种是“独立作答＋局部反馈＋完整参考”；每种都要有窄屏和暗色实例。示例必须由同一 builder 生成，避免手工做一张漂亮截图而默认生成器仍产出旧页面。
6. **把完整内容与当前舞台解耦。** 当前舞台只有一个明确目标和动作；完整推导、条件、评分与补充解释都可定位展开。辅助操作收拢为“学习工具”，保留已有功能。每个展开后的内容依旧服从字号、间距、颜色合同。

## 我下一轮审核的验收清单

| 检查 | 我需要看到的证据 | 通过条件 |
| --- | --- | --- |
| 首屏视觉重心 | 1440×900 与 390×844 的真实截图 | 首屏能辨认当前学习动作与主要数学对象；元信息不把它们推下首屏 |
| 主题统一 | 浅/暗两套首屏、活动、反馈、图形截图 | 不出现暖纸正文套绿卡、白色图块贴在暗背景等断层 |
| 图示可读 | 双图和单图真实 bounding box、截图 | 必要图字实际 ≥14px；坐标/端点/差值可读；缩放没有细线消失与重叠 |
| 语义连续 | 拖动 a、b 前后截图 | 同一变量在控制、图、公式中的颜色和形状不漂移；事件填充与差值对应 |
| 状态完整 | 首次、已选、正确、待修正、提示、参考、焦点 | 每种状态都有可见文字与形状；结果不靠颜色独立表达 |
| 对比度 | computed style / SVG fill 与相邻背景的计算记录 | 文字 ≥4.5:1；必要控件与图形 ≥3:1；透明层先做颜色合成 |
| 密度和层级 | 一个首屏、一段推导、一个展开工具的截图 | 一个主要动作；图比附属说明更突出；无三四层无意义套框 |
| 字体与数学排版 | 中英文、分数、上下标、积分同时出现的截图 | 公式风格一致；辅助字与按钮不微缩；200% 文字缩放不丢失功能 |
| 色觉与灰阶 | 灰阶检查及至少一种色觉模拟 | a/b、选中/未选、正确/待修正依然可凭文字、形状、线型辨认；模拟只作额外检查 |
| 生成持续性 | 同 builder 生成的 S2 与另一类数学页面 | 无需给每份结果手工补样式；token、布局和图示字典在两份都成立 |

我对冷白/墨蓝/铜橙方案的判断是：**准许进入实现，基线不通过最终视觉验收。** 方案表只证明选色有可行性；整体是否成熟，要看候选技能能否稳定约束真实 HTML，以及完整状态下的实际截图。

## 计算与参考

本文对比度均由代码按 sRGB 线性化及 `(L较亮 + 0.05) / (L较暗 + 0.05)` 计算；透明色先按当前背景合成。显示值四舍五入，判断用未舍入值。预估字号来自源码布局尺寸，尚未冒充浏览器实测。

[1] W3C, [Understanding SC 1.4.3: Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。普通文字 4.5:1，大文字 3:1；本文把 4.5:1 作为数学图中文字的统一门槛，避免小字号边界判断。

[2] W3C, [Understanding SC 1.4.11: Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。必要控件辨识与必要图形至少 3:1；并非要求所有装饰边线达到这个值。文档也提醒细线的实际抗锯齿显示可能弱于名义色值。

[3] W3C, [Understanding SC 1.4.1: Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)。信息、动作和辨识不能只由色相传递。
