我审查了实际候选 `SKILL.md` 以及 `references/visual-design.md`、`teaching-design.md`、`modes-and-explanations.md`、`interactive-html.md`。路径根目录为 `/workspace/scratch/b4c4b2db70f4/repo/plugins/dialogue-tutor/skills/dialogue-tutor/`。

本轮对象是技能文本是否能够持续指导生成，不包括仍在实现中的运行组件，也不包括尚未收到的真实 HTML 截图。我先通读五个文件，提出一次具体退回意见；修订到位后，只复查该意见及相关 Important 项，没有扩大审核范围。

## 我认为已经做好的部分

1. **呈现优先级成为入口规则。** `SKILL.md` 第 10–12 行明确写出“交互＞可视化＞文字”，同时把原题覆盖、数学条件和完整解答保留下来。固定幕次和字数不再决定首屏形状。这是从根上修正文字主导的办法，我认可。
2. **活动与视觉关系进入蓝图。** `SKILL.md` 第 27–37 行要求记录学习者动作、可观察证据、可视化关系、必要解释和下一步；还区分真正判断与空转按钮。`teaching-design.md` 的活动表进一步说明图形究竟承担什么关系。生成器由此有机会先构建学习任务，再安排版面。
3. **色彩已成为同一套可执行字典。** `visual-design.md` 的完整明暗 token 表沿用了冷白、墨蓝、铜橙方向，区分画布、工作面、辅助平面、正文、控制边界、动作与反馈。函数蓝、比较紫、参数 a 的铜橙与参数 b 的蓝青都有固定名字，后续生成不需要重新猜配色。
4. **文字宽度和图形宽度分开处理。** 视觉参考指定正文约 700–760px、舞台约 1040–1120px；依据单图实际宽度判断单双列，并检查 SVG 缩放后的字号。它准确回应了旧版嵌套双图仅约 10.74px 的问题，不再把 viewport 断点当作全部解决办法。
5. **完整内容与默认展开内容分开。** `modes-and-explanations.md` 第 24–30 行和交互参考的 studio 说明，把完整解释放入具名入口，含答案的说明通过 `solutionId` 关联。`visual-design.md` 将收藏、笔记、复制和来源收进“学习工具”，使主任务具有更明确的视觉地位。
6. **生成过程开始约束持续性。** `SKILL.md` 第 49 行要求先修改规则、数据或公共组件，再重新组装，不能手改成品掩盖技能遗漏；第 51 行明确旧样章只作兼容材料。第 55–59 行又把真实状态、明暗和窄屏检查纳入交付。这些规则比单独给出一组色值更有价值。

## Critical

### C1. 默认新页说明与唯一完整示例曾经继续引导旧布局：现已关闭

我初读时，`interactive-html.md` 的“任务舞台与表现分支”要求 studio 场景把 `bodyHtml` 收进关闭的完整解释，并禁止在其中嵌入活动；后面的“组装新页面”却无条件要求往 `bodyHtml` 预置挂载点。该节唯一完整 JSON 又没有 `presentation: "studio"`。按照同一文件对省略字段的解释，复制这个例子会得到 1.6.0 连续正文布局。

我将其视为阻断项，因为示例是生成器最容易照搬的部分。即使前面反复写交互优先，默认示例仍会把长文与末尾活动带回来，导致真实产物继续偏离设计方向。

我复查修订后的文件，确认：

- 第 179–181 行明确新课程按任务关系组织，使用 `presentation: "studio"`，区分 `lead`、`prompt` 与 `bodyHtml`。
- 第 188 行的完整 JSON 已明确写入 `"presentation": "studio"`。
- 第 200–203 行给出 `lead`、具名 `explanationTitle` 与 `activityIds`；第 209 行把题目关联到对应的自动全解 ID。
- 第 230–234 行将内嵌挂载点移入“兼容旧连续正文”，明确不用于 studio；第 259 行也区分旧页自建 details 与 studio 自动全解。

这些改动直接解决了我的原意见。我撤销这一阻断项，不再以旧版示例问题退回候选文本。

## Important

### I1. SVG 默认黑色与透明合成遗漏：现已关闭

原视觉参考虽然提供主题变量和对比门槛，但没有明确要求 SVG 普通文字设置 `fill`。基线恰好发生过父级正文换成浅色、图中 `<text>` 仍是黑色的失败，因此只写“暗色可读”不够具体。

修订后的 `visual-design.md` 第 35 行明确要求 SVG `text` 使用 `fill: var(--dt-ink)` 或相应语义变量，坐标轴使用 `--dt-control-line`。第 49 行又要求透明填色先与真实背景合成，再测最终对比。第 37 行保留轮廓、纹理或清楚标名的补充线索。它们分别覆盖文字默认值、实际色值和区域辨识三个不同问题，我认为文本层已经明确。

### I2. 状态验收原先偏重错误、遗漏正确和焦点等常见状态：现已关闭

我原先建议不要只检查首屏和错误提示。正确反馈、选中、查看提示与键盘焦点同样会改变颜色、密度和边界，部分状态还会引入新的浅色面板。

修订后的 `visual-design.md` 第 49 行明确列出首屏、图形、正确反馈、错误反馈、提示、选中状态、键盘焦点、展开全解和窄屏，并要求主题切换后重新检查；第 51 行继续要求截图与计算结果。这份状态清单已足够指导下一轮真实页面审核，我关闭此项。
