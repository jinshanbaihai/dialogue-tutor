# 教育学专家评审：1.7.0 候选全包

评审日期：2026-09-07。对象：`repo/plugins/dialogue-tutor/skills/dialogue-tutor/` 的当前候选技能、参考、builder、runtime 及兼容样章。本报告沿用已通过的文本层标准，检查这些标准与实际 API 的一致性。

**首轮裁定：退回修订，暂不批准独立生成正式课程。** 当前已有测试全部通过，但独立 DOM 探针发现辅助证据遗漏，另外两处生成契约与组件的真实行为不一致。下文保留具体观察与关闭条件；修订后只复查这些问题与新增教学参考。

## Strengths

1. **studio 在实际结构中先挂载活动、再提供关闭的全解。** builder `make_new_document` 把任务与 `activityIds` 放在场景全解之前；runtime 一次显示当前活动，导航不生成作答分数。现有 DOM 测试实际检查了冷启动、场景切换和自由导航。
2. **目标覆盖已经进入两个验证器。** builder `validate_lesson` 与 runtime `validateLesson` 都拒绝 studio 中没有活动的目标、遗漏或重复挂载的活动，以及不存在的分支目标。旧 schema 和旧连续正文仍有兼容分支。这实现了结构下限；能力与题型是否匹配仍由教学蓝图审查。
3. **四种主要客观作答情形有真实可达的后续任务。** 当前测试分别操作错误、提示后正确、无辅助正确和跳过，核对推荐 ID，并点击进入对应活动。跳过没有制造错误尝试；推荐也不封锁其他导航。
4. **共享全解对 quiz 的辅助标识已经处理到提交竞态。** 打开一处共享解答会标记关联的 numeric/open 题，且不会跳走当前活动；即使 native details 的 toggle 事件还未到达，提交时也检查全解是否已经打开。已提交的首次原答不会被后续反馈倒改。
5. **自评、探索与客观评分仍分开。** 开放解释和闪卡自评不会触发独立正确路线，steps 与 exploration 不产生答对记录。提示、揭示、同会话重试、到期复习和导入旧记录的边界有直接测试。
6. **保存与返回不止写在说明里。** 测试覆盖草稿、笔记、书签、自定义参数、当前位置、导出导入、不可用存储，以及到期开放题的未完成输入。自定义活动导航时保留原 DOM 节点，导入通过 `dt:restore` 恢复状态。
7. **兼容材料的已指出数学断点得到实质修复。** `s2-source.html` 的 CDF 端点理由不再回引后面依赖同一结论的第 12 行；对应概率公式引用改为第 9 行；对称性推出期望的句子补上期望存在条件。它们与 JSON 的 CDF 步骤、`q2c-answer` 条件一致。

## Important

### P1：预测 quiz 会在探索前主动揭示参考——待修订

**位置。** `interactive-html.md`“任务舞台与表现分支”允许“先出现的预测 quiz”接后续操作；runtime `reduceActivity` 的 submit 设置 `answerRevealed=true`，`quizReference` 在 studio 将参考 `details.open=true`。

**观察。** 我的 DOM 探针向名为 Prediction 的普通 numeric quiz 提交 `1/3`，随即得到 `answerRevealed: true`、`referenceOpen: true`，DOM 已出现参考概率与解释。尚未进行后续探索操作，待发现的关系已经被普通测验反馈给出。这是 API 行为，不是对某位学生反应的猜测。

**我的判断与联合方案。** 我与游戏策划共同确认：普通 quiz 的即时纠正适合测验，但不能直接承担需要暂缓核对的预测记录。最小修订是同一个 interactive 内“不评分的预测输入与提交→冻结原预测→具名操作揭示→与原预测比较”，之后另设独立 quiz。预测保存为探索/个人判断记录，不伪造客观正确。

**关闭条件。** 生成指令删除直接使用普通 quiz 暂存这种预测的配方；明确记录原答和时间、揭示阶段、参数变化与尝试序列，并覆盖初始化/恢复。最终生成物中验证提交预测后只冻结输入，在学习者选择操作后才呈现目标结果。主动查全解仍允许，须清楚保留辅助接触，不能声称此时仍是未见答案的预测。

### P2：共享全解辅助没有进入关联闪卡的卡片尝试——待修订

**位置。** runtime `createActivityView` 的 `solutionId` 观察器调用活动层 `reveal`；`flash-flip`、`flash-rate` 及闪卡复习读取卡片层 `exposure`/`recallAssisted`。当前 schema 允许 flashcards 带 `solutionId`。

**可复现观察。** 探针创建 flashcards，关联一个确实含卡片答案的全解。先打开全解，再翻面并选择“已回忆”。状态同时出现：

```json
{
  "activityExposure": {"reference": true},
  "cardAttempt": {"source": "self", "correct": true, "assisted": false}
}
```

这没有把自评改成客观正确；错误是遗漏了真实的辅助来源。现有“shared full explanation”测试只覆盖 numeric/open，没有覆盖 flashcards，所以 58 项通过并未排除这个反例。

**所需修改。** 让关联全解的接触进入它确实覆盖的卡片记录与后续复习判断；保留提交时的原记录，不倒改之前已经完成的无辅助回忆。若 `solutionId` 对整组卡生效，生成契约明确这一粒度；不要靠收窄文案而继续漏记已经发生的答案接触。

**关闭条件。** 全解打开后卡片自评保持 `source:self` 且 `assisted:true`；共享多卡、刷新/导入、近期接触后的回顾仍保留辅助；独立旧尝试不被倒改。实际没有读到答案的其他活动不被连带标记。

### P3：pathways 文档把辅助和错误写得比真实条件更窄——待修订

**位置。** `interactive-html.md` 将 `assisted` 描述为辅助后的客观正确，将 `incorrect` 描述为客观错误；runtime `pathwayOutcome` 还会在未作答但已经看提示/参考时返回 assisted，并在开放题/闪卡负自评时返回 incorrect。

**观察。** 我的 numeric 探针仅点击提示，仍为 `status:idle`、`attempts:0`，却已返回 assisted 推荐；开放题提交后选择负自评，`source:self`，返回 incorrect 推荐。runtime 的可见反馈正确注明“自评仍需练习”，所以问题不是 UI 假称客观判错，而是作者会按较窄文档编写不成立的路线标签。

**所需修改。** 保留有帮助的推荐行为，精确公开触发语义和优先次序：跳过、明确未通过（含注明来源的负自评）、已有辅助、无辅助客观正确。assisted 不等于已完成或已经正确；自评正向不能因此进入独立正确。同步教学参考中“只基于客观事件”的过窄描述。

**关闭条件。** 文档与实际分支一致；作者不会给未作答的提示使用者显示“辅助答对后进入”；记录汇总仍把原答、辅助、自评与客观判定分开。

### P4：兼容正文的两处理由仍与合法方法/题面依据不一致——待修订

**观察来源。** 我定点检查本轮修订的 source/JSON 对应时，读到了相邻的具体句子，没有扩展为历史全量数学调查。

- `s2-source.html` L394 把积分下限从负无穷改为 0 归因于归一化条件“在区间外面留下的 0”。归一化本身不决定支持区间；实际依据是题面规定 `x<0` 时密度为 0，因此这段积分为 0。
- 同文件 L1421–1424 把动手积分说成读错 `write down` 的信号，并断言耗时四五分钟；JSON `q2c-answer` 的追问则承认用期望定义积分能合法得到同一结果。简洁解法的优势不需要通过否定合法核对或虚构耗时建立。

**关闭条件。** 第一处改为明确的题面支持区间依据；第二处说明验证对称性后可以直接写结果、积分也可核对，并删除没有数据的耗时断言。其余已修复的 CDF 与期望存在条件继续保留。

## 与游戏策划已共同确认的接口

我们同意“不确定问题→冻结预测→改变可观察对象→一份样本形成一个统计量值→比较→不同题应用→具名后续或暂停”的循环。对总体 `{1,3,5}`、两次独立等概率有放回抽样，九个有序结果支持均值 1 与 3 的概率分别为 `1/9` 与 `3/9`。

手选样本属于枚举或演示，不能记为随机频率；一次抽样显示统计量点的来源，精确概率由样本空间与权重合并支持。改变样本量、放回条件与模拟次数分别有明确问题。进度和成就回应实际数学产出；点击数量、积分、随机好结果或停留时间不代替学习。复访若要形成提取记录，需要走会收起旧答案/输入的复习入口；普通 navigate 只代表浏览。
