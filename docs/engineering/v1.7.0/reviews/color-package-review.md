## Important

### I1. 所求区间曾只有低对比透明填色：定点修复后关闭

我初读的 CSS 第 240 行仍是：

```css
.dt-graph-area { fill: var(--dt-plot-function); fill-opacity: 0.38; }
```

这条规则没有区域轮廓、纹理或其他独立边界。JS 第 866 行的均匀分布密度图又把 `markers` 传为 `null`，所以支持区间内的所求子区间，其左右边界主要由透明色块给出。

我对实际背景合成后的颜色重新计算：

| 主题 | 填色与透明度 | 实际背景 | 合成色 | 对比度 |
| --- | --- | --- | --- | ---: |
| 浅色 | `#235CC7`，38% | `#FFFFFF` | `#ABC1EA` | 1.82:1 |
| 深色 | `#86B7FF`，38% | `#122238` | `#3E5B84` | 2.31:1 |

浅填色本身可以低对比；问题是区间两边缺少能够独立承担数学信息的表示。获准的视觉合同已经要求轮廓、纹理或清楚标名，此处是公共组件没有落实合同，并非临时偏好。

我要求的修复范围：

- 区域采用不透明语义边界或可辨认纹理，必要图形与实际背景对比至少 3:1。
- uniform 密度图标明事件端点；原始 a/b 与裁剪后的交集边界分别表达，越过支持集时不混同。
- CDF 的 `F(b)−F(a)` 与密度所求区域具有可见对应标记或紧邻的明确文字。
- 新增标签不全部挤进原有刻度带；必要时使用图外短说明。

初审时，我将此项退回公共组件修正。运行代理完成后，我重新读取实际 CSS 和 JS，仅复查这一受影响路径，并独立计算修订后的边界对比。

修订后的 CSS 第 240 行为区域增加 `stroke: var(--dt-action)`、`stroke-opacity: 1`、`stroke-width: 2` 和 `vector-effect: non-scaling-stroke`。填色可以继续保持轻盈，不透明边界已经独立承担辨识作用。

| 不透明边界 | 相邻颜色 | 独立复算对比度 |
| --- | --- | ---: |
| 浅色铜橙 `#A84420` | 白色图底 `#FFFFFF` | 5.98:1 |
| 浅色铜橙 `#A84420` | 区域内侧合成蓝 `#ABC1EA` | 3.29:1 |
| 深色铜橙 `#F0A16B` | 墨蓝图底 `#122238` | 7.64:1 |
| 深色铜橙 `#F0A16B` | 区域内侧合成蓝 `#3E5B84` | 3.30:1 |

我同时核对了两侧相邻颜色，没有只测外侧图底。修订后的 JS 第 808–841 行支持原始事件圆点与裁剪边界空心方框；第 884–897 行根据真实交集确定区域，只在有非零交集时绘制面积，且分别保留原始 a/b 与裁剪位置。CDF 使用同一原始 a/b，图外 `.dt-event-summary` 明确列出原事件、支持区间、交集与 `F(b)−F(a)`；额外 a/b 标签与刻度分行。源码层已经满足原意见，我关闭 I1。

生成参考仍需保留主代理承诺的“原事件端点与裁剪后边界分别标明”规则，避免未来自定义图形重犯同类问题；此次代码准入不依赖于手工修饰某一个样例。
