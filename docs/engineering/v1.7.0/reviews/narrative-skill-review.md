# DialogueTutor 1.7.0 候选技能：叙事与情绪感染评审

审查身份：我以编剧、叙事与艺术创作的专业审查视角承担本轮模型评委工作，不声明真人职业认证。审查对象为 `/workspace/scratch/b4c4b2db70f4/repo/plugins/dialogue-tutor/skills/dialogue-tutor/` 中实际存在的六份技能文件。此次只读并评审，没有修改技能，没有生成或检验成品 HTML，没有派发代理。

我把“有感染力”具体理解为：学习者知道眼前有什么尚未解释，能够亲自作出一个判断，看到行动产生可理解的证据，并且愿意在判断被修正后继续。数学中的差异本身可以承担情境；不需要为一条等式安排角色、冒险或虚构危机。我的意见针对能否稳定生成这种体验，不把停留时间、热闹程度或我的审美感受当成已测学习收益。

## 已成立的优点

1. 我认可 `SKILL.md:10` 将目标置于操作数量和装饰之前，且把交互、图形、文字连成同一条解释链。`teaching-design.md:62` 排除了没有额外学习用途的动画、奖励和重复点击。这给叙事留下了正确的位置：帮助理解这一次判断的必要性。
2. `SKILL.md:33` 的“可回答的挑战→操作或示例→可见结果→解释依据→独立新题”已有一个可用的推进骨架；`:35` 允许查看全解、跳过和返回。我认为这比固定七幕更适合数学节奏：关键关系出现时推进，学习者需要支架时可以停下。
3. `SKILL.md:37` 保存原预测，`modes-and-explanations.md:26` 区分例题和评估，`:34–38` 保护伴读中的首次作答。原判断被保留，后面的结果才有可能形成真正的呼应。
4. `modes-and-explanations.md:18` 把原题的抽样条件、范围和精度落入必填槽位，`:14` 又限制无关历史和编造争论。我认可这种约束。若情境靠改变有无放回、独立性或未知参数制造“惊喜”，感染力就以错误数学为代价。
5. `visual-design.md:37` 保持同一量的视觉语义，`:45` 把动画限定为解释状态变化。这使情绪推进可以来自“看见关系发生变化”，不会迫使作者另造一套戏剧配色。
6. `expert-review.md:22–29` 要求从空白独立生成、检查真实文本与行动，并把退回意见先写回技能。我认可这个验收范围；仅有一段漂亮示范不能证明整个技能会持续生成相同品质。

## Important

### I1：流程已有挑战与结果，生成合同却没有要求二者通过学习者原判断形成呼应

**逐句依据。** `SKILL.md:27` 要求“学习者动作、可观察证据、可视化关系、必要解释”等蓝图字段，尚未要求记录“眼前尚未解决的一个问题”和“结果如何回应它”。`:33` 给出五段流程，但没有规定结果需要和先前判断比较。`interactive-html.md:85` 说 `section.lead` 承载“简短场景与必要目标”，`:181` 说“只放必要场景”，两句都未定义什么使一个场景必要。`expert-review.md:14` 虽列出“情境需要、悬念、讲述节奏、反馈情绪”，这些词尚未进入生成配方。

**我的判断与影响。** 这是实际文本缺口。按现有合同，作者完全可以生成“学习抽样分布→请选择→答案错误→下面学习统计量”并满足流程名目，结果没有回答开场的需要，也没有承接学习者做过的事。是否已经生成这种页面属于待测情形。它影响的是用户明确要求的感染力，因此不能只作为可选润色。

**建议写入技能的配方。** 讲述性任务的作者蓝图补充五项：`当前需要／一个可回答的悬念／承载判断的动作／揭示时点与可见证据／回应原判断及下一步`。这些属于作者材料，不要求把新增字段原样暴露在页面或假装现有运行时已经支持新 schema。

可采用如下技能句：

> 需要讲述时，用一至两句交代一个当前要解决的数学需要，再提出建立在已给前提上的单一问题。情境可以是数学对象之间的差异；仅在现实背景解释该需要时加入背景。学习者先预测、分类、计算或说明，再以实际结果回应原问题。保存了原预测时，结果文案据其内容分支：一致则指出哪项证据支持它，不一致则指出具体差异；没有保存预测就不代称“你原来以为”。结束用已出现的证据收住开场问题，并给出一个具名下一行动。

同时应保留例外：直接查定义、要求完整答案或已知前提不足的短问题不必强造悬念；先提供所需支架。不能把每个小活动都扩展成角色剧情。

**复查方法。** 修改后我会检查一条真实核心路径，从进入任务到结束逐项找到开场问题、本人动作、揭示证据和回应句。分别输入相反预测与正确预测：前者应看到可解释的差异，后者应看到具体验证，不能两者都收到“没想到吧”。跳过者不能收到声称其完成了判断的叙述。

### I2：探索验证型预测与普通 quiz 的反馈时序存在歧义

**逐句依据。** `interactive-html.md:96` 规定“预测→探索采用先出现的预测 quiz 或自定义提交记录，再由具名操作揭示结果”。`:115` 同时规定 choice “明确提交后给对错与解析”；`:117` 的 open 也在提交或主动揭示后显示参考。因此普通预测 quiz 的一次提交可能已经给出目标结果，而文案仍要求接下来通过探索揭示。`SKILL.md:37` 的预测冻结原则没有解决这两种揭示时点的区别。

**我的判断与影响。** 这是实际指令歧义，不是已经实测的运行故障。如果尚未操作，提交预测就显示正确答案，后面的“看看结果是否支持你的判断”会成为一个答案已知的表演。它也容易使作者误把观看已知结果当成首次预测验证。

**建议写入技能的条件规则。** 不必因此强行增加组件：明确分开两种任务即可。

> 若 quiz 提交本身就是验证，提交反馈可以揭示答案，后续图示用于解释已知结果。若任务声称先预测、再通过探索验证，普通即时评分 quiz 不承担未揭示预测；使用能够冻结原输入的自定义 interactive，明确保存预测、揭示、重置及恢复状态，待具名操作之后显示目标结果。预测的保存只记录判断和参与，不冒充独立正确证据。

我还建议将已有“不能提前泄露”落实为同一目标的展示检查：首屏标题、`lead`、图形初态、默认选项、按钮文字、可访问文本及伴读前行轨都不能抢先公布本次要预测的结果。主动打开全解仍然允许，并按已有辅助规则处理；不把情节悬念当成封锁求助的理由。

**复查方法。** 我会先填写预测但不运行，确认当前合同规定的揭示时点；然后执行揭示，观察结果及呼应句；再刷新、重置和导入记录，确认没有篡改原预测或借恢复状态提前泄题。若采用提交即验证型 quiz，则验证后续文案准确说“解释这个结果”，而不是声称结论尚未出现。

### I3：错误反馈有诊断原则，缺少让学习者恢复行动的情绪配方

**逐句依据。** `SKILL.md:35` 要求“错误反馈指向当前误解与修复动作”，`:69` 要求“肯定落实到具体推理或修正”；`teaching-design.md:34` 允许进入补救活动，方向正确。实际可照写的范例 `interactive-html.md:218` 却只给“这个选项把某个位置的高度与区间面积混淆”，没有立即可做的修复。`:183` 已说明这个例子是最小结构，因此我不把它缺少整章路径判为缺陷；我指出的是反馈句本身尚未体现前述修复要求。

**我的判断与影响。** 规则允许作者知道要“修复”，却仍以诊断名词代替修复动作。更重要的是，数字错了并不充分说明错误机制；自信断言“你把某概念混淆了”可能误诊。学习者需要看见当前差异可以缩小、下一步可以完成，才有继续的情绪空间。

**建议写入技能的配方。**

> 错误反馈先指出已观察到的答案或步骤差异，再给一个能够立刻执行的局部检查，修正后具体说出这次改变了什么。反馈评价当前推理，不评价智力、努力或人格；没有过程证据时不虚构错误原因。只看到错误数值时，先邀请核对一处关键关系。正确反馈指出被证据支持的关键选择；借助提示完成时认可已完成的修正，同时如实保留辅助来源。跳过或先看示例后提供可进入的下一步，不归咎于懒惰或失败。

可把示范反馈改成类似：“这里选择了用单点高度判定合法性。先在图上区分高度与一个小区间的面积，再检查概率条件约束的是哪一个量。”具体组件必须确有对应操作或图示；不能承诺不存在的检查入口。

**复查方法。** 用一个可诊断的干扰项、一个原因未知的错误数值、一次提示后正确和一次跳过走实际页面。每次检查反馈是否与真实记录一致、修复动作是否可执行、完成修复后是否有具体回应。不能只检查“没有负面词语”；“再试试，你可以的”若没有修复办法，仍未满足本项。

## Minor

### M1：数学讲述的逻辑順序明确，句间节奏仍可操作化

**依据。** `SKILL.md:67` 与 `modes-and-explanations.md:26` 已规定“用途与依据→一般关系及条件→代入”。这是充分的数学组织底座，但仍允许写成三块并排长文，缺少从刚出现的证据走到下一判断的连接。`interactive-html.md:126–128` 已正确限制把每个等号拆成按钮，我不建议反向恢复强制步进。

**建议。** 增补：“每个讲述段落围绕一个关键选择组织，先指向刚观察的差异，再给解释它所需的条件与关系，最后回到当前题目的量。常规连续运算保持连贯，不为节奏拆成每等号一按钮；需要停顿时把停顿交给一次有数学意义的判断。公式之后用一句话说明它如何回答眼前问题。”这不是机械字数下限，也不要求把已经能连贯读懂的推导重新碎片化。

**复查。** 读取一段实际抽样分布解释：任一句“因此”都应能追到此前条件或图形证据；任一活动停顿都应有一个可回答的判断。若只有“接下来”“让我们继续”的连接词，记录具体位置再修。

### M2：叙事验收责任明确，但尚缺最小的双预测与修复体验检查

**依据。** `expert-review.md:14`、`:23` 要求核查实际文本、学习者行动及结果。`interactive-html.md:315–328` 有充分功能检查，但未明确列出“预测正确与预测错误得到不同且如实的回应”“错误修复后被具体接住”。

**建议。** 在叙事评审责任中增加：抽查一条核心问题线的预测一致、预测不一致、辅助修正与跳过路径；对照原题条件检查情境；只承认实际显示的文本和动作，不用作者意图代替结果。无需为每道题添加新表演，也无需把全部页面重复检查一遍。

**复查。** 在最终评审记录中保存这些实际活动 ID、输入、关键输出文案和结论。照片美观或审读者“觉得有趣”不能代替这些记录；真实学习者是否受到感染仍需用户体验证据，不由模型审查伪造。

## 可直接采用的短任务配方示例

下例是我为说明技能配方写的自拟微型例子，不是正式 Pearson 原题，不是已经生成的课程，不要求独立生成者照抄。它不替代原章材料核对。

| 时点 | 数学内容与学习者动作 | 叙事执行规则 |
| --- | --- | --- |
| 条件与需要 | 总体为 `{1,3}`；独立地连续抽取两次，每次等概率、有放回，以两次结果的平均数为统计量。 | 全部条件在可见题面出现；情境无需增加角色。 |
| 可回答悬念 | “平均数为 1、2、3 的机会会一样吗？先保留你的判断，再把有序样本按平均数归组。” | 只问一个差异。这里给出可能均值，不给出它们的概率。第一次接触有序样本者可先看别的数据的简短示例。 |
| 本人动作 | 学习者提交预测，再把 `(1,1)、(1,3)、(3,1)、(3,3)` 与其平均数对应并归组。 | 若探索承担验证，预测提交阶段不评分或揭晓；归组承载真实数学动作，不用无关点击凑互动。提供键盘可操作形式。 |
| 可见结果 | 四个有序样本各有概率 `1/4`；均值 1、2、3 的概率分别为 `1/4、1/2、1/4`。 | 结果出现时同步显示样本到统计量的归并依据，不靠动画戏法改变概率。 |
| 预测不一致时 | 若本人预测等可能：“归组后，均值 2 对应两个有序样本。把这两条路径的概率合起来，再和另外两组比较。” | 指出导致差异的可见证据并给动作；不写“你肯定没想到”。 |
| 预测一致时 | 若本人预测不等可能：“你的判断得到这次枚举支持：均值 2 对应两条等可能路径。现在说明为什么应当把它们相加。” | 正确也有结果呼应，但不凭二选一预测宣布已经掌握一般方法。 |
| 修复与呼应 | 若学习者确实完成正确归并：“这次合并了通向同一均值的两条路径。开场问的是均值是否等可能；枚举说明，不能只数均值有几种，还要合并对应样本的概率。” | 只有实际完成后才使用“这次”；未完成时使用中性参考说明，不伪造进步。 |
| 下一步 | 进入另一道数据不同的独立枚举题，自行确定所有有序样本、对应统计量和概率。 | 下一步具名且确实存在。只改变数值时按既有规则标为同构练习，不能冒称结构迁移。 |

我希望采用的是“需要—判断—证据—修复或验证—呼应”的短配方，而不是把上表八行做成八次强制翻页。页面可以紧凑，解释依然可查；当完整答案是用户眼前需要时，直接展示完整答案仍然成立。
