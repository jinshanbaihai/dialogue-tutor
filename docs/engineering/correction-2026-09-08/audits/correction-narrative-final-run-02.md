## Important

### I1：辅助身份仍覆盖了答错事实，收束与接续没有回应原判断

位置：course.js 96 行 `mainOutcome()`、121–123 行 `renderEnding()` 及 `chooseNext()`；冻结 HTML 中同一实际活动脚本。

独立步骤：新窗口 → 原生 summary 打开 `main-reference` → 选择 `equal` → 保存本条件判断 → 显示 bars（实际 Image 回调 fixture）→ 结尾 → 点下一行动。

实际冻结记录保留 `choice: equal`，辅助为 `main-reference-wr`。两概率已正确显示，但收束仅说“你的提交前已有相关参考，这是有辅助核对”，没有说明所选“一样可能”与结果不一致。下一按钮是“构造尚未呈现的有放回新数据”，实际进入 task-wr，未进入错误修复。证据见 focused 文件的 `assisted-incorrect` 与 `assisted-incorrect-next`，全套也独立重现相同组合。

问题在于结果分类先返回 assisted，后续再用这个互斥值决定反馈和路线。虽然底层 choice 没被删除，叙述和动作已经丢掉错误信息。这正是批准技能要求“正确性、辅助、已见分别保留”的实际失效，不能以每个字段仍存在判通过。

修订方向：在生成规则中要求先独立计算本条件的判断结果、参考身份和结果覆盖，再分别组装句子；结果已见且判断不一致时必须具体回应差异，辅助信息另句保留。后续建议同时依据是否仍有错误，不能让辅助分支遮掉错误支持。复验至少覆盖有/无辅助 × 正确/错误，并检查实际句子和点击目的地，不能只各跑一条“正确”和“辅助正确”。

### I2：主线的错误补救仍只有答案摘要，缺少完整推导及精确返回

位置：course.js 114–116 行 `repair()` 的 `main-map` 分支，实际 `#repair-panel > #repair-equal`。

独立步骤：新窗口 → 无参考选择 equal → 保存 → bars → 结尾 → “检查每种输出的原像”。实际面板只有 mean1 的 AA 与 1/9、mean5 的 AC/BB/CA 与 1/3，加一句“先找原像，再加权”。没有三项 1/9 如何相加、3/9 如何约为 1/3 的小步；面板没有任何返回当前主行的链接、后续动作或局部完整解释。focused 证据保留整个面板 outerHTML，确认不是提取遗漏。

正文中确有这些完整推导，但这个自称修复的入口没有把当前差异送回那些内容。它让读者再次看到结果而仍需自行寻找缺的依据。构造板的错误反馈能提供相应原行链接，不能替主线这个独立分支通过。

修订方向：让每个实际错误入口引用本条件的完整补讲内容与原行映射，至少展开当前断点所需的权重、互斥相加及必要约分，并给准确返回位置与可选接续。生成验收读取每个可达 repair 面板的真实内容和 href 语义，不能仅凭 `repair-equal/weight/reverse` 三个名字存在或正文别处有答案通过。无需复制整章，也不能省掉本断点真正需要的小步。
