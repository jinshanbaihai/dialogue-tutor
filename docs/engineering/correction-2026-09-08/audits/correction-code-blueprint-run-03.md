## I1：静态公开答案的presented缺少实际视口判据

第43行仅说明祖先hidden/closed-details/display/visibility；这只能排除被隐藏的节点，不能区分视口内与屏幕外公开正文。③包含完整结果且保持连续公开，如果把这些静态节点一律按“祖先可见”采集，则页面初次提交/导出时可能把尚未滚到的两组目标概率都记为已呈现；主问题不再处于真实待核对状态，首答也会被屏幕外正文污染。

必须按source kind落实不同判据：

- 静态`presented`：节点及祖先显隐通过，并有非零矩形与当前viewport相交；或者学习者确实通过具名定位动作到达该真实行。仅节点在DOM中、已挂载或CSS非隐藏不够。
- 主动`reference`详情：真实summary默认动作已使open改变，且节点及所有祖先真实可见；submit/import/export同调用队列读取这个当前状态。不要让屏幕外静态正文通过这个分支。
- `frame`：只有当前requested的成功回调提交到displayed且当前图式可见才记来源；请求、失败、迟到成功不算。

共用同步扫描仍在submit/beforeImport/beforeExport，scroll/observer只能补充。contact是历史，不以恢复该历史伪造当前viewport；visibleSolutionIds只展开实际已揭示详情。对本题6与4两个目标分别存覆盖，看到其中之一不足以表示两项结果已呈现。

试件用矩形fixture测“目标6屏内而4屏外→尚待；4也屏内→两项已见；另机制不继承；open但祖先隐藏→不记”，并保留明确定位真实行的入口验证。它仅证明JS分支，不认证浏览器滚屏。

## M1：空集回答意图须有一个自洽状态规则

第22行同时使用`draft.paths=null`、数组及`pathAnswered`；只明确专用空集按钮会设true，又把取消最后一个路径解释成已回答空集。后者已有真实动作及界面提示，不把它直接定为违反“默认零勾选未答”，但现在的字段关系仍容易在ready/恢复中出现矛盾。

选择并写清一种规则即可：推荐将取消最后一项回到未答，只有具名“我的路径集合为空”设置显式空集；或者保留现行为，但明确取消最后一项当场显示空集判断且置相同意图标记。无论哪种，列出null/空数组/非空数组与pathAnswered的一致性约束，勾新路径撤销空集状态，newAttempt复位。入站矛盾状态拒绝，不静默补成已答。映射缓存允许合法未选路径的旧选择，ready只要求当前已选路径；不把缓存键强行限为当前所选路径，否则与第23行“重选恢复本人选择”冲突。

## M2：主预测三个选项的错误分支不宜预设错误原因

第32行WR只写“把mean输出等可能”，但WR另一个错误选择是“小于”；WOR的“大于/小于”也不能仅凭预测选择推断学习者沿用了旧权重。完整支持的数学链可复用，但入口标签及回应应按实际原选择说“不一致，请比较这两组原像”，只有实际收集了对应理由才诊断等可能/旧权重。蓝图补全WR两种错误与WOR两种错误的中性对应，仍复用同条件完整推导，不新增无关repair。
