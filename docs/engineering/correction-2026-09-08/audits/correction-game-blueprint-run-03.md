## 当前设计中已有内容后果的循环

主问题把“能算一次平均”与“哪种平均更常见”接起来，先让A→B给出4，再让学习者比较均值6和4。本人按题面独立核得：WR中6的原像AC/BB/CA共3/9=1/3，4的原像AB/BA共2/9，故前者较大；WOR中两组各2条、每条1/6，均为1/3。切机制让第一次关系变为相等，确实改变要协调的条件，而非只换按钮名。

后续maximum题保留R/S不同身份但相同值1，这给路径资格与数值归并两个不同判断：WR中maximum1有RR/RS/SR/SS四条，概率4/9，maximum5概率5/9；WOR中maximum1只有RS/SR，概率1/3，maximum5概率2/3。range例与Q4的均值事件、组内无放回/组间重抽则是进一步改变目标和独立性条件，不只是扩大数字。这里支持“具有不同数学要求的后续任务”，不支持一次选对就证明广泛迁移。

三个旧失败根因在本蓝图已分别有可实施约束：

- **不完整与数学错误分开。** default paths=null且未回答，专用空集/取消最后项有明确状态；本人选择的映射、权重和分布必填。ready只检查完整合法，不能把数学上错的全集/概率和拦住；完整空集可冻结为错答。未完成只指出待填，不公开答案或消耗首答。
- **正确性与辅助分开。** 两个比较目标均实际呈现后才核对；原选择大于/相等/小于如实回显，辅助另句。WR选小于不能被诊断成“误认等可能”，WOR错误也不能被断言成“沿用旧权重”；v2对此给了实际回应。参考后错答仍先推荐当前差异repair，同时保留自由全解与跳过。
- **修复能回到判断。** 主比较repair直接给原像→权重→互斥求和→约分/比较。构造按missing/extra、映射、权重、分布分别给当前条件完整支持或精确原行。返回与重开是两个动作，目标绑定owner/condition/submissionId；切条件后旧repair不误送新条件，首答和已见来源保留。

预测尚未呈现时不把内部计算能力当可见证据；只见一个目标时邀请查看另一个，既不报对错也不提前送repair。保留完整正文与主动全解，不把“避免提前泄露”改成必须答对才能阅读。主路径radio/checkbox/select/button及原生翻卡免打字；笔记独立，不向学习者追加表达困惑或确认弹窗要求。

## M1：下一任务及真实回访缺本课具体路由表

蓝图写了“错误优先repair”“已冻结目标标回看”“点击时getState重新决策”，但尚未列出mean-lab各结果后实际去哪里、max WR/WOR完成或已见后如何选择另一条件/Q4，以及recall-core两卡不同完成状态时采用哪个真实review item。

这些规则方向正确，缺口是当前课件具体落点，不是已有矛盾。因此列Minor，允许先搭已明确的组件试件；在组件交审前补一个表即可，不增加题量。每行至少给：当前owner/condition、presented/answered/correct/assisted事实、目标是否已见或冻结、按钮实际文字、target活动+条件、动作种类、点击时重算来源。

需要覆盖：

1. mean两机制的未呈现、只观察、正确无辅助、正确辅助、错误及跳过；错误首选本条件repair，尚未呈现只给实际验证入口。
2. max当前条件正确或跳过后，另一条件未见、已见未完成、已冻结，以及两条件都完成时去Q4还是回看；不能把已锁答卷继续称为“新挑战”。
3. recall-core卡0已有真实review、卡1背面打开但尚未自评时，浏览、继续未完成、提前练习、到期分别定位哪个index；从getReviews获得完整真实item，缺item时转初次任务/继续工作，不能伪造到期记录。

这个补充用于阻止“按钮看起来有下一步，但目的地或回忆状态不对”的旧风险。已把可执行修改交给`correction_author_03`，并与`correction_education_03`协商分工。
