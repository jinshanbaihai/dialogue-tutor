先记录最终交付路径与 HTML、lesson JSON、数学数据、Scene、manifest、实际使用媒体及技能输入的 hash。HTML 内嵌的运行时、组件脚本与 JSON 单独提取并记 hash，防止只核查作者源文件却漏查实际交付字节。只测试正式交付的一致版本；若运行期间作者更新文件，记录版本差异并请根冻结对象，不把不同版本的成功拼成一次通过。

在独立评审脚本中用 `repo/node_modules/jsdom` 加载**最终 HTML 原文及其中实际内联 JS**，不另行 import 作者脚本替换它。为每个独立场景建立隔离窗口与存储；恢复场景保留真实导出和存储数据。按真实 ready/mounted 状态等待并设置诊断超时，不用任意延时猜测完成。收集 VirtualConsole、window error、未处理异步失败及实际挂载清单；保留栈、活动/条件和最后操作，区分课程错误、预期存储失败和 jsdom 能力缺失。

通过正常页面按钮、radio/checkbox/select/range 的 click/change/input 等事件操作；观察最终 DOM、公开状态/导出和资源请求。不会直接改组件内部状态、偷调评分函数、预设通过标记或替换题目数据。先从真实题面与控件清单确定条件和选项，再据教育评委独立数学核验选取正确/特定错误输入；作者给出的答案仅作为待比输出。

## 三、媒体证据必须对应 DOM 实际请求

1. 正式HTML里若用data URL，将该次DOM引用解码，记录MIME、长度及字节hash，与manifest对应文件hash比较。若用交付目录相对路径，按真实HTML基址解析、只读交付资源并记录文件hash；不把开发目录中同名文件当交付资源。若用blob或动态资源，记录真实生成来源及能取得的字节；取得不了则列未核，不用URL字符串代替字节。
2. 从实际事件后的frameId/URL反查manifest的condition/stage/line/path/bar。核对每个实际引用文件存在、格式可识别、数据hash与Scene源码hash及作者渲染记录对应；列出未被UI使用的文件而不把它们算作已显示。真实Manim生成身份还需源码/命令/产物记录与真实画面审阅支持，hash本身不证明渲染工具。
3. 归属和概率数学期望取教育评委独立录入题面后的核验结果。图像是否正确显示高亮、文字与轴交给打开真实静帧的独立画面/数学评审；本评委若打开图，明确逐份记录，不把媒体文件存在写作已目视通过。
4. 不依赖视频播放也应能完成冻结要求中的任务；静帧按实际入口检查。若有视频，字节/清单检查与播放时序检查分开记录；jsdom不支持的播放、seek或真实图像显示仍未测。没有视频的课程不要求新增视频测试。
