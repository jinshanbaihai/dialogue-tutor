## 原版与当前代码的具体优缺点

- 原版 olct 定义橙标题、绿公式、红陷阱、蓝题面、紫标签（第8–9、64行），有清楚的文档角色约定。逐问讲解以白纸、深墨、适量暖色建立层次；已看旧推导截图中，公式和依据可同时读取，局部底色强调一句结论，值得保留。
- 原版也把绿色用于公式、答案、教师说话、图线等不同概念；这些文档角色不能直接搬成数学对象色。多种大面积淡彩卡片连续出现会让“颜色表示章节种类”压过“颜色指向数学对象”。
- 当前代码已有独立 success/error、control-line、focus 和浅深主题 token（第13–42、371–394行），比把所有边框和文字共用浅灰更可靠。
- 当前 --dt-parameter-a 与 action 同色；区域填充为函数蓝而边界为操作橙（第244–246行）。这套通用函数图约定不适合作为抽样课角色表：用户按橙按钮不应误以为操作本身是一个数学参数。
- 当前图 viewBox 宽420，文字20（第239、1257行）；实际宽度若降至280，文字只约13.3 CSS px。代码中的20不是手机实际20。当前存在40px高通用按钮与更小步骤按钮，不宜照抄。

## Critical

**C1 数学对象身份不得被状态色或章节色覆盖。** 建立共享 JSON 色表及 object-id 映射，Manim 和 HTML 均读它。X₁ / 第一次观测、X₂ / 第二次观测、统计量分别固定蓝、紫、青色；筹码身份由数值及编号识别，不给9条路径分配9种颜色。选错后，公式里的 X₁ 仍然蓝，外侧显示“× 这条依据不成立”及错误边框。不得把所有对象变红或答对后全变绿。

通过条件：至少对有放回9路径、合并均值、概率柱图、无放回6路径四种真实帧，逐对象核对 Scene、HTML 公式、选项中的颜色和标签；每帧有 manifest，包含 object-id、role、label、token、精确数学值、步骤 id。关键关联不能只靠颜色：X₁ 用圆形/“第1次”，X₂ 用方形/“第2次”，均值用菱形/“均值”；排序、文字符号保持一致。

**C2 不能把桌面全景缩成手机小字。** 九条有序路径在手机上用3×3矩阵，行标“第1次”，列标“第2次”，单格显示有序对；每对的平均值计算放在紧邻的 HTML 当前推导行。逐对构造时高亮一个单元并保持其余数值可读。不要在一幅窄画布里同时塞九行算式、完整树、柱图和图例。

通过条件：360/390 CSS px 宽分别截图；页面无横向溢出；图中数值标签实际高度目标≥16px、关键符号≥18px；现有低对比度未选路径不能靠 opacity 0.2 处理。若上述尺寸不能达到，应拆帧/拆图或换手机构图，不能以“可放大”免除首次阅读要求。

## Important

**I1 图像主题必须真实适配。** 不用 CSS filter/invert 改 Manim 光栅图。浅/深主题分别从同一 Scene 数据渲染，picture 或 JS 选择与页面一致的版本，宽高固定防跳动。允许先完整提供单一浅色主题，但此时明确 color-scheme:light；不能暗页夹一个无说明的亮白视频。Manim 缺少暗版时，不声称双主题通过。

**I2 保持主次，不制造视觉噪声。** 页面暖灰底、白色正文/作图区、深墨正文；只给当前问题一个明确操作色。正文标题用墨色，细短标记可用操作暖棕。已读推导行保持正常对比度，用左侧细线或行号标识当前行，勿把已揭示行灰到难读。薄网格可淡，数学边界、零柱标记与可选目标不能淡。

**I3 有放回与无放回的数学比例保持真实。** 并列柱图共用纵轴范围（例如0至1/3）和同一数值横轴；2、3、4、5、6、8应按数值距离放置，不用等距类别假装连续数轴。概率0显示基线处空心标记与“0”，被排除路径加斜线及“不允许重复”，不只消失。两种机制以标题、实心/轮廓或分面区分，不替换 X₁、X₂、均值色。

**I4 控件和内容可读。** 正文17px/行高1.8，手机最小16px；选项正文16px、按钮16px/最小高44px；辅助说明14px且保持对比度。公式默认18px，含分数/上下标宜20px。窄屏逐行推导用“行号+公式”一行、“依据”下一行，仍是一条数学变换及其依据；不强制三列横向缩字。长公式在合法数学断点分行。

**I5 真实帧与即时反馈分工。** Manim负责数学对象与变化，HTML原生按钮负责选择、焦点和反馈；不要把可点击按钮画进视频。下一步只推进相邻数学变换；暂停状态仍完整可读。prefers-reduced-motion 使用同源静帧，不能黑屏或丢掉中间依据。

## Minor

- 去掉非必要渐变与大面积彩色底，保留平面底色、细边线、8px以内圆角。
- 章节标题、反馈标题、关键对象是有限的视觉强调，不同时给全段加粗、上色、加底、加阴影。
- 图下注明当前方案与步骤；信息性字幕使用 HTML，避免把整段中文压进视频。

## Manim画布与手机规格

推荐桌面单图4:3，渲染1600×1200；手机专用构图4:5，渲染1000×1250，HTML容器满可用宽度。手机360px宽、左右各16px时图宽328px：图中文字在源PNG实际字形高度至少约49px才能约为16 CSS px；关键符号至少55px。**Manim font_size 不是实际像素字高**，必须量PNG包围盒并在截图核验。9路径矩阵与最终概率柱图分帧/分面；中文长解释放HTML。320px宽容器的16px目标要把源字形高度提高至50px，或用更窄专用构图。桌面图不要求塞下所有故事，正文推导承担精确算式。

## 已执行的数值验证与可执行后验

已用WCAG相对亮度公式计算上表非透明纯色的最坏值（分别对canvas/surface/surface2三底色）。这仅验证调色板，不是浏览器/Manim实物验证。

|---|---:|---:|
|正文ink|12.098|11.790|
|辅助muted|5.021|7.324|
|X₁|5.156|7.088|
|X₂|5.270|6.736|
|统计量|4.990|7.780|
|control-line|3.130|4.045|
|action文字色对三底色|5.739|6.938|

success/error/hint/focus对三底色亦分别超过4.5；浅色最小为5.155，深色最小为7.432（这组不含action）。对比度阈值执行时不能四舍五入后判通过。采用普通文字≥4.5:1、必要非文字图形与组件≥3:1；本文更大的字号目标是设计要求，不冒称WCAG规定所有图标签16px。

下列Python可对导出的最终纯色pair清单执行（fg/bg必须为最终合成后的#RRGGBB；透明色先按实际底色合成；threshold按文字4.5/必要图形3设定）。产物例：[{"id":"light-x1","fg":"#2364AA","bg":"#FFFFFF","threshold":4.5}]。

```python
import json, sys

def luminance(h):
    s=[int(h[i:i+2],16)/255 for i in (1,3,5)]
    c=[v/12.92 if v<=0.04045 else ((v+0.055)/1.055)**2.4 for v in s]
    return sum(v*w for v,w in zip(c,(0.2126,0.7152,0.0722)))

failed=[]
for p in json.load(open(sys.argv[1])):
    low,high=sorted((luminance(p['fg']),luminance(p['bg'])))
    ratio=(high+0.05)/(low+0.05)
    print(p['id'],f'{ratio:.6f}', 'PASS' if ratio>=p['threshold'] else 'FAIL')
    if ratio<p['threshold']: failed.append(p['id'])
if failed: raise SystemExit('Failed: '+', '.join(failed))
```

后验必须包含：

1. 从浏览器computedStyle获取正文、依据、链接、选项default/selected/hover/focus、正确/错误/提示、按钮文字与实际背景的颜色；覆盖浅深主题。不要只扫描:root声明。
2. 从Manim帧实测图底和主体线/字的颜色，检查有无意外半透明、视频编码色差；数学数字和符号按文字门槛。不要在抗锯齿边缘随便取一个像素代替实际前景色；同时看最终缩放是否过细。
3. 360×800、390×844、1280×900，至少浅深各一套；记录页面HTML、Scene源、PNG/MP4哈希与实际步骤。200%文字缩放检查正文/控件不遮挡；图文相邻、不强制横拖整页。
4. 逐一执行选错→补讲→新检查→查看全解→前后步→切主题→减少动态；截图证明选错不改数学对象身份，已揭示的依据持续可读。
5. 灰度截图检查仍能依靠标签、形状、位置识别X₁、X₂、均值与状态。色觉模拟可作辅助，不以单个模拟器截图证明“对所有色觉障碍无障碍”。
