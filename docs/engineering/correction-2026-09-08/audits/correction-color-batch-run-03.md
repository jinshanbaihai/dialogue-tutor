## 实际像素与颜色

独立 `probe.py` 按单个字形的语义色墨迹测量，未用整体 Text bbox 或 Manim font_size 代替正文主体。1490 个需要按字体验收的数字、字母及汉字：普通最小 **62 源px = 17.36px@280**；关键最小 **70 源px = 19.60px@280**，满足既有 16/18px 门槛。等号等运算符按其真实形状目视，没有把等号的细横杠强行放大到汉字墨高。分数数字在最窄目标宽度可辨。

线宽通过对独立生成的 280px PNG 的法向颜色覆盖积分测量，采用每条四处内部截面的最小值；不是 stroke_width×缩放的参数推算。

## C / I / M 与组装条件

**C：0；I：0。M1：货架底部说明的连接可更明确。** 图内“实心柱：均值 ≥ 7”下紧接三项全分布求和，却没有其余分布图的“总概率”小标题。当前 manifest caption 已明确事件只含输出 7，数学并未错，故不是重要错误。最小处理是在最终该帧实际可见 caption 加：**“下方三项之和检查全分布总概率；实心柱对应事件的概率为 1/3。”** 不需改变角色色，不需为这处说明重渲染全部图。

此前代表图的轴义/WOR×说明和来源 hash 问题已落实：当前 21 个 chart caption 都写了横轴统计量数值、纵轴概率，WOR overview caption 解释 ×，全部 Scene hash 一致。此批准把 **PNG 与该帧 caption 视为组合部件**；不是声称 bar-focus 原图内部已有完整轴名。最终 HTML 必须实际显示当前帧 caption，不能只把它留在 JSON。

最终完整 HTML 仍需单独检查：实际祖先 CSS 和图像内宽不能低于本次 280px 证据预算；当前请求/显示图、caption、公式、目标与来源锚点一致；异步失败和迟到回调不留下旧语义；MathML 完整分数的角色与样本量常量区别；每类真实控件背景的对比度。未测真实浏览器布局、原生 MathML 像素、浏览器图片解码、触屏、键盘或放大。本文不是这些项目的通过凭据。
