## 一、四组构造：保留草稿错误，不从正确集合反向修正UI

草案给出的两条路都可行，生成时选择一条并明确证明首答保护：

1. **由本人勾选生成映射行。** 行集合严格等于本人的`draft.selectedPathIds`，即使误选AA也保留其行。删掉某一勾选时如何处理对应映射草稿要明确，不用标准允许集合自动纠正；不能只显示“六行”或自动补全缺项。
2. **所有候选保持可见。** 九个身份候选都允许选择“本抽法不允许”或给映射，正确集合不能由某些行缺席、禁用、预选或默认颜色推断。题面声明候选全集可以，但不能把其中六条称作已经确认允许。

第3/4组的完整分布和概率备选本来可包含正确答案；问题是是否通过唯一标签、固定正确行或自动淘汰把前组的判断直接做完。因此依赖表要检查每组目标与其它组**给定的信息**，不要写成禁止任何相关选项共存。

冻结前只能检查合法选项ID、是否已经回应必要项目，不按正确性帮助补完答卷。提示或全解仍可主动打开，相关接触须按程序席同步采集合同记录；不以“保护首答”为由锁阅读。

## 二、补入原像多选的精确 missing／extra 合同

这是run-01游戏I3的直接缺项，应新增一行修订落点到teaching-design、interactive-html及实际生成蓝图。不要只写“错误给补救”。

对当前`conditionKey`与目标统计量事件，用已冻结选择集合S和同源精确映射所得目标集合C，提交后计算：

- `missing = C − S`：每条遗漏的**身份路径ID**、两次观测、逐行统计量结果、路径概率、属于目标的依据、加入目标求和的那一项。
- `extra = S − C`：每条多选的身份路径ID、实际统计量结果、为什么不满足当前目标。如果路径在当前机制中本就不允许，先指出身份／条件不合法，不给它套有效路径概率。
- `matched = S ∩ C`：只说明这批已选路径符合；集合尚不完整时不能说“你已构造全部分布”。

UI先保留本人原选择，紧接着明确“少选CA”“多选AA”等可核对差异，配当前对象的依据。每条差异给准确的`pathLineId`与`groupSumLineId`，再给一个真实存在、答案未提前揭示的新数据检查。没有缺漏时说明完整原像与概率贡献；空白草稿只说尚未提交。勿凭这些选择推断粗心、努力或心理状态。

固定作者DOM断言至少四种：只漏、一多、同时漏多、完全正确；另做两个**相同选项数量但不同成员**的错误集合，防止实现只比条数。检查具体missing/extra身份、对应结果/权重、回行目标和未揭示新题。正确集合来自模型结果，不由作者手写第二份答案。

## 三、补入 current draft 与 history 的可见身份合同

run-01重试后“尚未提交”与旧“本次核对”同时显示。草案需要明确两种状态分开：

| 对象 | 最低字段／语义 | UI要求 |
| --- | --- | --- |
| 当前草稿 | 当前条件、draftId或generation、选项、editing/submitted状态 | 只描述这一份未提交/待核对的选择 |
| 已冻结提交 | submissionId、条件、原答、核对、提交时辅助快照 | 不可被后续反馈、重试、恢复改写 |
| 历史反馈 | 对应submissionId和已接触参考身份 | 若重试时保留，明确叫“上次核对／历史参考”，不能叫当前草稿的“本次结果” |
| 新条件挑战 | 真实条件身份和未揭示目标 | 必须改变具体判断要求，或诚实标同构新数据；不能只是重置旧答卷或换活动ID |

新尝试可以关闭旧反馈，以便集中判断；已发生接触仍保留。这与回忆入口需要先题后答案是UI安排，不是把已见同题重新洗成独立。答错不封锁新尝试、全解或其它目标。

作者DOM断言：提交A→重试草稿B，A的冻结数据不变；B的标题、状态和核对区不能冒用A；随后提交B有新ID和正确辅助；旧导入既不能覆盖冻结A/B，也不能让历史答案假装成当前草稿。未提交B刷新后继续B，不能把“从未提交”改成一次新成绩。

## 四、把四状态下一行动写成可执行的数据合同

草案开场问题字段方向正确，应进一步要求蓝图提供以下作者数据，不能把它们只写在散文中；这不是未经实现的runtime schema。

| 字段 | 必须指到的真实对象 |
| --- | --- |
| `openingQuestionId` | 页面上一个具体、可回答的问题节点；例如所问目标事件，而非整章标题 |
| `conditionKey` / `targetQuantity` | 当前条件及实际求问的量／事件，能从同源精确数据重算 |
| `resultSource` / `resultLineIds` | 结果从何处读取，哪些已显示行/图支持，不手抄默认答案 |
| `hasDisplayedEvidence` | 实际揭示或可见结果的事件条件；没有证据时不虚构发现 |
| `responseSnapshot` | 提交过的原判断及提交时辅助身份，不由目前控件选择反推历史 |
| `responseClass` / `comparison` | 四种身份与具体数学一致/不一致分别保存；有辅助且正确仍保留辅助 |
| `nextAction` | 真实targetActivityId/题目条件、清楚标签、新增判断要求、查阅/继续/新题/复习类别 |

四种身份对应的数学回应与下一步不能都是同一按钮：

| 真实身份 | 回应需要表达的事实 | 默认具名下一行动 |
| --- | --- | --- |
| 无辅助，判断与证据一致 | 哪条路径/条件/关系支持了这次判断，只称本题核对 | 一个明确改变条件或统计量的题；已做过时选择另一个尚可验证目标或诚实回看 |
| 判断与证据不一致 | 原判断与当前证据差在哪；必要时列missing/extra | 指向这一差异的局部检查，再给未揭示新题；不强制做对 |
| 未提交／跳过 | 尚没有本人判断；已展示结果与否分别说清 | 具名示例、直接全解或仍可做的原任务，不能说已经证明 |
| 提交前已参考／提示 | 本题借助何种支持完成；仍可报告数学一致性 | 另一道未揭示的新数据/新条件题；未有合适新题时明确继续或回看，不伪称独立 |

若没有已显示结果，四分支都不得提前公布受保护的新题结果，只给下一验证动作。若学习者主动揭示，回应数学事实并保留参考身份。不要把“辅助”混成“辅助后一定正确”，也不要把“无记录”混成“已独立正确”。

页面需要完整知识收束，因此已显示结果时，先回答开场具体问题，再给上述分支和可选下一目标；次数可放收起的记录面板。用户可停止或查看全解，不按正确性解锁。

固定作者DOM断言：四种身份通过真实控件建立，收束分别断言问题ID、当前条件、数学量与原判断身份、具名链接实际到达；再改一个真实可选条件，验证没有套用默认结果。任务已完成时再点新挑战，不能返回同一锁定答卷并称新挑战。回看本题可以保留，但须准确命名。只换数字的活动称同构练习，真实结构变化写清新增哪一判断。

## 五、回忆与停续：保持草案的接口精度，再加多卡及草稿判据

草案真实review item传入`navigate(id,item)`正确。特别加上run-01实际失败状态：第一卡到期、当前在第二卡背面时，入口必须以item.cardIndex选择第一卡并先给正面。不能只导航活动ID、也不能每次强制回第0卡。

提前练习与到期复习区分标签，使用既有重试/闪卡重启的真实流程；不得改dueAt或伪造未来时间。普通浏览保持旧页面状态，未完成草稿继续原工作；这三个动作不是同一个“继续”。测试中模拟时钟可以验证分支，但必须标为环境模拟，不能作为真实延迟学习证据。

同步接触采集须包含本次仍显示的历史答案、当前打开的原生details与图式结果。先采集→与可信本页记录及导入记录合并→保存→恢复显示，不能只等toggle。学习者能续读还需重绘真实open范围，不能只保存revealedThrough数值。
