## I1：参考后的错答被辅助分支覆盖

**实际路径 G02 assisted-incorrect：**原生打开 `#main-reference summary`，选择 `equal`，立即保存判断，显示 WR bars，再点击真实“直接到本次收束”。记录保留 `choice=equal` 和 `assistance=[main-reference-wr]`，当前数学结果也正确显示 1/9 与 1/3。可是收束只说“你的提交前已有相关参考，这是有辅助核对”，不再指出原判断“一样可能”与结果不一致；唯一下一项为尚未呈现的 D/E/F 构造。无辅助的相同错误会显示“不一致”，所以不是题目缺少比较规则。

**实际路径 G05：**打开 q3b 全解，无放回完整选六条正确路径和正确映射/分布，权重选 `old`。冻结记录 `check.correct=false`、`check.weight=true`，且有 q3b 参考来源。具体权重反馈仍出现，这是优点；但唯一下一项是未呈现 WR 构造，不再提供该错误的 repair-weight 入口。点击后实际进入 WR，确认不是只有标签错误。

原因可定位到 `mainOutcome` 和构造 `nextButton` 调用：先判断 assistance，才检查答案正确性。它把两个独立事实重新变为互斥类别，违反已批准收束/后续合同。应从 `correctness` 与 `assisted` 两字段共同生成回应；参考后错误仍明确指出差异并给当前条件修复，另可提供未揭示任务。下一轮生成检查至少交叉覆盖“参考×正确/错误”，不能只各测一条互斥分支。

## I2：未完成四组也立即冻结并公开剩余答案

**实际路径 G08：**新构造板仅勾选 `DE`；不填 DE 映射，不选权重，三个分布格全部空。点击“统一提交四组”，页面立即生成 active 冻结提交并公开 missing、正确映射依据、权重和全部分布反馈。保存草稿清楚显示 `paths=[DE]`、`mapping={}`、`weight=null`、`distribution={}`。

这不是蓝图允许的“明确提交空路径集合后核对 missing”：本次选了 DE，而且其余必答组没有填写。也没有选择自由全解入口。`submit-construction` 直接创建答卷并调用 `checkDraft`，没有作答完整度检查，因此一次尚未完成的提交消耗了该题的首答机会，并把后续工作转成已见答案后的核对。

生成时应先判本人已选路径所需的映射、权重和分布格是否已作答，未完成只指出缺失的输入组，保留草稿与首答状态。路径集合的数学正误在统一提交后检查；允许空集的显式判断仍可保留。对应 DOM 断言须使用“仅路径组已选”“漏一个映射”“权重空”“分布缺格”等实际未完成输入，不以完整错误答卷代替。

## I3：补讲停在反馈副本，缺少完成修复后的接续

**实际路径 G11：**主例选择“一样可能”后看 bars，从结尾点击“检查每种输出的原像”。repair-panel 给出 mean1 的 AA 和 1/9、mean5 的 AC/BB/CA 和 1/3，再说先找原像、再相加。它没有本处逐项相加/约分的小步，没有通向这些完整推导行的链接，也没有可答的核对或下一任务、返回当前判断的控件。实际读取 repair-panel 的 `a/button/input/select` 集合为空。

**实际路径 G04 的三种构造错误：**遗漏 DE 且多选 DD、沿用旧权重、直接把输出当等可能，各自进入正确名字的 repair。局部区域复制原冻结反馈并附一段相同的通用检查话语；存在指向具体原行的链接，但没有返回构造草稿或进入下一次核对的动作。三次均由评审另行找到原构造板的重开按钮才继续，补讲本身没有完成约定的后续路线。

这不表示没有具体数学反馈：缺 DE/多 DD 明确区分两个 2 的身份以及 1/6 与 0，权重错误给 1/3×1/2，归并差异给真实原像；G11 实际点击 DE 和 DD 的原行链接均成功，不能把它们误报死链。问题是主例局部补讲缺完整小步入口，构造补讲未把已知差异带回可执行核对。

下一轮按每个 repair 生成具名合同：当前错误/条件→本处补全的计算或可打开的完整原行→需要重新检查的具体判断→返回当前草稿或实际新核对的目标。复用已有推导和题目即可，不要求新增题量或逐等号强制点击。实测从错误进入补讲后，只用页面给出的实际接续控件完成这一轮；不要以评审直接调用 runtime.navigate 代替学习者入口。
