## 已有实现的实际优点

1. `presentation` 默认已经是 document；`make_new_document()` 允许正文内的 `data-dt-activity`，只为未嵌入的活动追加节尾挂载。恢复新生成默认主要是纠正 SKILL/参考文档与作者模板，不应破坏 studio 分支。组装器还检查挂载恰好一次、唯一静态 ID 和唯一 placement 锚点。
2. 现有 choice 在提交前不判分；quiz 提交先冻结尝试，再记录参考接触；flashcards 将自评记为 `source:self`。不需要删掉旧 numeric/open 来实现新课免打字。
3. interactive 首次内容保留 DOM，不随笔记、推荐或面板更新反复替换。`dt:activity-mounted` 在微任务中派发，届时 `DialogueTutor.instance` 可用；`dt:restore` 与真实探索事件分离；`restoreExploration()` 能同步保存恢复合并而不增加操作次数。这些是可复用的可靠边界。
4. 路径建议及 studio 前后导航本身不是答对门锁。保存按 lessonId/revision 隔离，导入校验身份和活动形状，已有旧版 exposure 推断逻辑，应保留其兼容责任。

## Critical

设计本身无必须推翻的 Critical 项。以下实际产物情形将升级为 Critical：主流程需要输入文字/数字；做错就不能看完整推导；首次新题被图、旁侧全解或步标题自动送出答案；没有实际 Manim 渲染却宣称真实帧；刷新/导入后将已经看过答案的同题重试冒称首次独立构造。

## Important

### I1 正文静态挂载与组件动态内容必须分层

`assemble()` 只扫描当时静态 document；`interactive.bodyHtml`、`steps[].bodyHtml`、错误补讲是运行时才进入 DOM 的字符串。因此把被 quiz 引用的 `solutionId` 放进 interactive 内，当前组装器会报找不到；动态 fragment 的重复 ID 也未纳入静态唯一性检查。runtime 在 `createActivityView()` 时只绑定当时存在的 solution，之后不重查。活动挂载只循环一次，且按 `activities` 顺序查询，不能依赖嵌套活动晚出现后自动补挂。`refresh()` 也不是重新发现挂载接口。

**最小方案：**所有活动容器、精确推导行锚点、引用的关闭 `details` 都置于 `sections.bodyHtml` 静态正文；互动组件内部只含自己的按钮、图帧和状态。禁止活动嵌套在另一个 activity.bodyHtml/steps/remediation 内。动态组件内部 ID 加活动前缀，并在组装时解析这些 fragment 检查冲突和不允许的嵌套。自定义脚本只在 `dt:activity-mounted` 绑定一次，在 `dt:restore` 调同一纯绘制函数，不在顶层假定节点存在。无需引入 MutationObserver 或动态 mount API 来做本样章。

这也避免把重要定义和已揭示主行放进一段会被 `replaceChildren()` 删除的 quiz 反馈。若确实要动态扩建课程，必须另设计幂等注册/卸载接口；不能作为本轮隐含能力。

### I2 “前后步”需要区分当前位置与已揭示范围

现有 `renderSteps()` 只渲染当前一步，所有步骤标题始终可见且可跳转；`stepIndex` 是唯一保存字段。它不实现“已揭示推导一直可查”，还可能通过写着结论的后续标题泄露答案。原版 steps 可继续兼容，不宜静默改变所有旧课行为。

**最小方案：**完整推导留在静态正文，以稳定 `lineId` 标识；组件保存 `currentFrameId` 与 `revealedThrough` 两个概念。回退只改变当前高亮/帧，不撤销已经开放的行；重置参数也不撤销已见结果。当前 checkpoint 后续部分暂藏在静态关闭 details，提交任意有效答卷、跳过后选择继续、或主动“直接看完整讲解”都可展开；展开不依赖正确。若作者使用自定义渐进显示，须保证无脚本时全文可读。

学习者打开前提→读其定义→返回当前节点时，必须保留视野中的已揭示链；现有 `navigate()` 只滚到活动，不能保证展开其隐藏祖先。最小布局应使活动和前提锚点不在默认隐藏容器内；必要时导航先展开对应祖先并记录实际参考接触。

### I3 免打字整份构造答卷没有现成客观评分接口

现有 quiz/choice 只收单个字符串选项；四个独立 quiz 会逐项反馈而泄露未提交部分。interactive 可保存复杂选择，但其公共事件只计探索：`validateImport()` 明确禁止 interactive 含评分 attempts；不能把正确性偷偷塞进探索后让总面板显示为独立通过。

**本样章最小可行方案：**一个 interactive 包含路径集合、均值映射、概率依据、分布四组原生选择控件，一个“提交完整构造”按钮。组件内保存完整答卷和客观核对结果，显示“新题构造选择核对”；runtime 总面板仍只记探索，不冒称它已经接入通用独立核对/到期调度。字段写清来源为组件的确定规则核对，绝不伪造 runtime attempts。首次提交冻结全部选择，再统一反馈；双击不重复提交；修改需显式新尝试。错因反馈只能说该选项对应某种可能混淆，不能推断心理原因。

若要求它参与统一客观成绩/推荐/复习，则实施前选择扩展 `quiz` 格式为整份构造选择，并同时更新 Python/JS 验证、评分器、渲染器、导入形状、证据文案。可把规范化选择编码为既有字符串 draft/attempt.answer，保存兼容较简单，但仍需严格检查所有组和选项 ID。不要通过 DOM 偷点隐藏 choice 或任意正确性事件绕过评分契约。两种方案只能明确采用其一，不能一边用探索实现一边宣称完成统一评分。

默认生成规则应拒绝主流程 quiz/numeric、quiz/open、可编辑文字/数值答案控件；排除可选笔记及只读上下文复制框。仅检索 `<input>` 会误杀 radio/range，也漏掉脚本动态创建输入；须实际贯通检查。

### I4 答案接触必须覆盖所有真实入口和对应条件

目前 solutionId 只能绑定一个静态关闭 details。quiz 提交同步检查它是否 open，补足异步 toggle；flashcards 也有同步接触捕捉。自定义组件不能假定这个机制自动涵盖“展示最终分布”“播放到答案帧”“打开另一处完整讲解”。普通 interactive 的 followups 不受 quiz 的 answerRevealed 条件保护，若在那里放当前新题答案会立即可展开且没有逐入口的自动追踪。

**最小契约：**每一题/条件有稳定 `conditionKey`，包含筹码身份和值、放回机制、抽取次数、统计量目标和内容版本；有 `referenceCoverage` 映射答案入口→覆盖哪些题。单次提交保存 `assistanceAtSubmit`，提示、全解、结果帧各有来源和时刻。图与正文都不得在首次提交前自动呈现当前新题结果；主动全解允许，打开当刻合并相应接触。所有入口走同一组件函数，提交动作再同步检查当前可见全解/结果，不能只等 toggle 或视频事件。

提交后的解释不能倒改刚刚冻结的首答；重试、回退、关上details不能洗掉接触。训练例题和真正新条件分别判覆盖，不能“一次看例题=全章永远辅助”，也不能“换了DOM id=新题”。客户端答案会存在 JSON/资源里，这里保护正常学习界面的顺序，不宣称具有防查看源代码的保密性。

### I5 Manim 需要明确数据、帧和正文行三者契约

当前组装器仅内联 CSS、JS、课程 JSON，不复制图片/视频、不执行 Manim，也没有帧映射验证。给 JSON 加个视频 URL 或把 `stepIndex` 乘一个时间间隔，不足以证明真帧和推导对应。

**最小同源输入：**一个精确数学 JSON 为唯一事实源；有理数用约分整数分子/正分母表示。由同一生成函数产出有放回9条与无放回6条有序路径、每条权重、均值和归并柱；Scene、正文算式/表和组件选项核对都消费这份数据。不在 HTML/JS/Scene 中手写三套概率，不拿格式化浮点文本反算概率。

**最小帧 manifest：**`dataHash`、`sceneSourceHash`、实际渲染版本/命令、每个 `frameId` 的 `conditionKey`、`stageId`、`lineIds`、`pathIds`、`barIds`、静帧文件与哈希；视频可选记录文件哈希和真实导出的对应时间/帧索引。例：点一条路径→选中两枚筹码、同一均值式和对应柱的预渲染高亮帧；切无放回→对角消失且余下路径权重同步变为1/6。数量有限的机制×步骤×高亮状态先列清楚，避免临时组合成无文件的状态。

前后按钮确定选择 manifest 中的静帧，不能只切旁白；视频作为可选过程播放。若同步视频，等媒体元数据及 seek 完成后才宣称切到对应帧；静帧更适合精确定位。快速连续点按要防旧图片加载晚到覆盖新选择；只在当前请求的帧可用后提交图式可见状态。缺帧须可诊断并保留同条件文字解释，不能回退到另一个条件的旧图。减少动态时仍选同源静帧、全部题可操作。

交付前决定资源随 HTML 目录打包还是嵌入。不能把只内联运行时的 HTML 宣称已携带外部 PNG/MP4；移动交付目录后须验证真实路径。本轮只做前置批判，尚未核验 Manim 能否实际运行或任何帧内容。

### I6 恢复应恢复学习场景，并合并已发生接触

runtime 的 `exploration` 是普通 JSON，内部字段不受课程语义验证；导入时只有通用形状检查。当前 `prepareSession()` 为已发生在本页的 runtime exposure 提供保护，但不会合并任意自定义 `contacts`。自定义状态要在 mounted/restore 时验证 conditionKey、合法帧、路径、选择组和版本，拒绝不属于当前数据的组合，不能恢复到“无放回且对角被选中”的图。

建议组件快照至少包含：`stateVersion`、`dataHash`、`conditionKey`、`stageId`、`currentFrameId`、`revealedThrough`、`draft`、`submissions`、`contacts`；保存 ID 和理性数据，不保存 DOM、图片字节或函数。真实操作发 `dt:exploration`；恢复从入站参数/草稿与本页已发生接触求合并，冻结提交快照不重写，再同步 `restoreExploration()` 保存后绘制。接触只能增补，不能因为导入旧草稿而消失；恢复不得新增操作、尝试或时间戳意义上的新揭示。

现接口 exploration 上限100000字符；不要每次播放时间更新都写历史，也不要把每帧编码放进状态。选择有限帧和具名操作已足够。保存失败时读图与做题仍继续，导出保留当页记录；不得承诺刷新必然恢复。组件实现若没有统一提交 API，须连同自身接触/答卷序列一起验收，通用 runtime 测试无法替代。

### I7 兼容边界要显式，文档不能给生成者互相矛盾的指令

| 边界 | 应保持或修改的契约 |
| --- | --- |
| 旧 studio 课程 | 保持 sections.activityIds 和自动全解 details、单场景导航；新生成默认 document 写入 SKILL 和示例 |
| 旧 numeric/open | 继续能读、答、导入；用新生成策略约束免打字，不全面删除 schema 支持 |
| 旧 steps | 保持原单步语义；本轮连续正文/帧控制用明确新组件或可选新字段 |

无需为了恢复 document 改 schemaVersion。若增加全局 graded 类型、导入 evidenceSource 或 attempts 对象结构，则必须同时确定版本/迁移，不能只改前端按钮。

## Minor

M1 `destroy()` 只撤去探索监听，没有卸除所有既有 view/toggle 监听；本样章使用单次页面生命周期即可，不引入热卸载再挂载。后续若支持热替换，需完整 dispose 机制。

M2 长正文记录面板位于标题后，应默认轻量收起，以真实数学任务为主。新组件用 button/radio/fieldset 的原生语义；当前帧描述、选中路径、条件和目标柱文字可读，键盘焦点不能因更新跳走。颜色之外仍须有路径编号/标签/边框。

## 最小实施顺序与实物验收

先定静态锚点及数据/帧/接触契约，再恢复文档默认和正文，接入免打字组件，最后真实渲染并组装。不能在图帧尚未产出前给课程“真实 Manim”通过。

| 教学场景 | 必须实际完成的动作 | 判断依据 |
| --- | --- | --- |
| 从定义进入构造 | 首次打开→阅读前提→正文内选择活动→回到前提再返回 | 活动确在相关行；定义未被整体折叠；无空节点；已揭示链仍可查 |
| 点路径理解归并 | 点任意一条，随后点反向路径 | 两抽值、均值式、目标柱与 manifest 及真实帧一致；反向路径独立贡献被看见 |
| 条件改变 | 有放回→无放回→前后步→回有放回 | 9/6条路径及1/9、1/6正确；对角删除和重新赋权同步；回退不混机制 |
| 完整新题构造 | 不键入，完成四组选择并统一提交；含错误选择、修改、双击 | 提交前无逐项判分或最终图答案；一次冻结整份答卷；双击不重复；证据标签真实 |
| 三类错误后继续 | 分别选等均值等可能、漏反向、无放回沿用旧规则 | 各有具体小步补讲和真正新题；任一错误都能继续和直看全解 |
| 答案接触时序 | 未答先看全解/结果；与提交同一动作队列；提交后看解释再重试 | 无异步竞态洗白；刚完成首答不被倒改；后续同条件答卷保留来源 |
| 恢复可见场景 | 在半份草稿、错误后、已看结果、回退帧分别刷新/导出导入 | 草稿、条件、图帧、当前行、已揭示链一致；导入旧记录不抹本页接触；立即导出仍有合并 |
| 首次动态挂载 | 空状态加载与带记录加载，每个自定义活动均操作；刷新面板后再操作 | 一次绑定；多个组件不串状态；restore 不增加探索/提交；无内部动态 solutionId 丢失 |
| 图资源交付 | 从最终交付目录打开，连点前后，暂停/重播，减少动态，窄屏/键盘 | 帧存在且与最终哈希匹配；迟到图片不覆盖新帧；静帧完成同一任务；不靠视频播放推进解锁 |
| 旧课回归 | 用旧 document、studio、choice、numeric、open、flashcards 及旧记录完成各自原操作 | 旧行为和导入仍成立；新生成仅主流程免打字；不同revision明确不混用 |

每个场景需保存最终 HTML/JSON、数学数据、Scene、manifest/媒体哈希和对应操作截图/记录。源码断言、测试通过数、作者承诺均不能替代上表的数学场景。当前仅可判“接口可落地、条件已指出”；没有最终产物证据，不能判课程通过。
